Executable examples and capability admission

CUDA and graphics compute

How to use these examples

Learn to select a resource, admit the exact feature it needs and order its GPU use. First read resource ownership and data layout, command recording and synchronization, and backend initialization.

The mental model is allocation → view/binding → recorded use → submission → completion → reuse. A capability admits an operation; it does not establish a resource's state, memory residency or queue ownership. Creation can still fail for invalid descriptors or exhausted memory.

Short snippets are literal excerpts from compiled GoogleTest workloads. They use ASSERT_TRUE/EXPECT_EQ to make failures visible. Adapt those checks to your application's status handling. Variables and helpers are initialized in each linked complete example; snippets are not separate standalone programs. The complete examples show allocation, binding, execution, readback assertions and cleanup.

cmake --build build --config Debug --target ArdaBackendTests
ctest --test-dir build -C Debug -R ArdaBackend --output-on-failure

Use the platform's actual executable directory for direct --gtest_filter runs. Shader artifacts and fixtures are deployed by the test build. Missing validation skips dependent GPU tests; see validation setup and failure diagnosis. A capability skip is not evidence that the skipped operation ran.

One allocation, ordered graphics and CUDA access

A CUDA-compatible buffer or texture can have two API representations of the same allocation. Representation availability is an allocation fact. Read/write states and queue ordering are separate facts. All CUDA work uses the same public command-list recording sequence. Native modes embed launches in the graphics API command stream; context-switching mode retains CUDA batches for separate execution between completed graphics segments. Applications do not toggle a CUDA-only queue owner.

Buffers supply a private linear device address, with view offset already applied. Textures supply a surface handle for one mip, including its array layers or depth. The public API deliberately supplies neither a general CUDA-runtime pointer conversion nor an OptiX handle conversion.

Start with FArdaCudaCapabilities and inspect FArdaCudaResourceInfo for each resource. CUDA device support does not imply that an ordinary graphics allocation was created for sharing.

const auto Cuda = Device->GetCudaCapabilities();
const auto Representation = Buffer->GetCudaResourceInfo();
if (!Cuda || !Representation.mbSharingEnabled) {
    // Choose a registered graphics implementation or report Unsupported.
}

Enable CUDA or build without it

The default build excludes the CUDA provider. Supply CUDA 12.0 or newer headers for ordinary-context execution; CUDA 13.3 or newer also enables D3D12 CiG capture. Driver loading remains dynamic; installing headers does not prove that the running adapter supports CiG. Vulkan native kernel launch uses Vulkan extension declarations, not a CUDA runtime library.

cmake -S . -B build/cuda-on -DARDASHIR_ENABLE_CUDA=ON -DARDASHIR_CUDA_INCLUDE_DIR="C:/CUDA/include"
cmake --build build/cuda-on --config Debug --target ArdaBackendTests
cmake -S . -B build/cuda-off -DARDASHIR_ENABLE_CUDA=OFF

Use actual local SDK/build paths. Public RHI headers compile with either setting. An enabled build with missing/old required headers fails explicitly; an unavailable runtime device reports its reason through GetCudaCapabilities. A CUDA-only operand then returns Unsupported. Registered graphics alternatives remain usable in both builds.

Create buffers and qualify textures

Set mByteSize and usage before allocating a buffer, then set mbCudaInterop=true to request sharing. A request can fail: do not allocate an ordinary buffer and later change a flag. Both providers admit dedicated, nonempty device-local buffers. CPU-visible, sparse/tiled, virtual/placed, versioned and acceleration-structure storage buffers are rejected.

FArdaRHIBufferDesc Desc;
Desc.mByteSize = 1024;
Desc.mUsage = EArdaRHIBufferUsage::ShaderResource | EArdaRHIBufferUsage::UnorderedAccess;
Desc.mbCudaInterop = true;
auto Shared = Device->CreateBuffer(Desc);
if (!Shared) {
    // Inspect Shared.mStatus; choose a graphics allocation/alternative if appropriate.
}

Surfaces support raw R/RG/RGBA integer channels at 8/16/32 bits and floating-point channels at 16/32 bits: 24 formats. Qualified dimensions depend on the selected launch mode: ordinary D3D12 contexts and native Vulkan support 1D, 1D array, 2D, 2D array and 3D. Vulkan context-switching supports 1D, 2D and 3D; layered surfaces are rejected. Check the selected mode and layered-surface capability before creation. Normalized/sRGB/BGRA/packed/compressed/depth, cubemap and multisample images are rejected. Native imports cannot request sharing without provider-owned export/mapping lifetime. All other resource kinds, including views, AS, micromaps, feedback objects, samplers and pipelines, remain non-CUDA objects.

Understand surface addressing and tensor packing

Surface instructions access typed storage; they do not sample/filter a texture and do not perform normalization, swizzling, sRGB conversion or tensor layout conversion. Use byte offsets in the surface x coordinate where the PTX instruction requires them. Mip dimensions, array layer indexing and 3D depth must match the selected binding.

A kernel expecting contiguous NCHW/NHWC tensors cannot consume an opaque tiled image as a flat pointer. Use an explicit surface-to-buffer packing operator and record it before the tensor operator. Keep format/layout conversion in that operator so the generic binding contract stays independent of the tensor library.

The source-backed surface example below writes a nonzero mip and checks it through graphics readback:

Surface kernel, binding and readback example
TEST_P(ArdaCudaGpu, SurfaceWritesReachGraphicsReadbackAtSelectedMip)
    {
        const auto C = mDevice->GetCudaCapabilities();
        if (!C || !C.mbSurfaceAccess) GTEST_SKIP() << C.mSurfaceUnavailableReason.c_str();
        const char* Ptx = R"ptx(.version 8.0
.target sm_70
.address_size 64
.visible .entry fill_surface(.param .u64 surface, .param .u32 width, .param .u32 height)
{
 .reg .pred p; .reg .b32 r<8>; .reg .b64 s;
 ld.param.u64 s,[surface]; ld.param.u32 r0,[width]; ld.param.u32 r1,[height];
 mov.u32 r2,%ctaid.x; mov.u32 r3,%ntid.x; mov.u32 r4,%tid.x; mad.lo.u32 r2,r2,r3,r4;
 mov.u32 r3,%ctaid.y; mov.u32 r4,%ntid.y; mov.u32 r5,%tid.y; mad.lo.u32 r3,r3,r4,r5;
 setp.ge.u32 p,r2,r0; @p bra done; setp.ge.u32 p,r3,r1; @p bra done;
 mad.lo.u32 r6,r3,r0,r2; add.u32 r6,r6,101; shl.b32 r7,r2,2;
 sust.b.2d.b32.trap [s,{r7,r3}],r6;
done: ret;
})ptx";
        FArdaRHITextureDesc D;
        D.mbCudaInterop = true; D.mWidth = 54; D.mHeight = 38; D.mMipLevels = 2;
        D.mFormat = EArdaRHIFormat::R32UInt;
        D.mUsage = EArdaRHITextureUsage::ShaderResource | EArdaRHITextureUsage::UnorderedAccess;
        auto Texture = mDevice->CreateTexture(D); ASSERT_TRUE(Texture) << Texture.mStatus.mMessage.c_str();
        EXPECT_EQ(Texture.mValue->GetCudaResourceInfo().mSupportedRepresentation, EArdaCudaRepresentation::Surface);
        FArdaRHIStagingTextureDesc Staging;
        Staging.mTexture = D; Staging.mTexture.mbCudaInterop = false; Staging.mCpuAccess = EArdaRHICpuAccess::Read;
        auto Readback = mDevice->CreateStagingTexture(Staging); ASSERT_TRUE(Readback);
        auto Cmd = mDevice->CreateCommandList(EArdaRHIQueueType::Graphics); ASSERT_TRUE(Cmd); ASSERT_TRUE(Cmd.mValue->Open());
        FArdaCudaKernel K;
        K.mPtx = Ptx; K.mEntryPoint = "fill_surface";
        K.mBlockSize[0] = K.mBlockSize[1] = 8;
        K.mGridSize[0] = 4; K.mGridSize[1] = 3;
        K.mArguments = {FArdaCudaArgument::Binding(0), FArdaCudaArgument::Value(27u), FArdaCudaArgument::Value(19u)};
        FArdaCudaBinding B; B.mResource = Texture.mValue; B.mMipLevel = 1; B.mAccess = EArdaComputeAccess::Write;
        const auto Dispatched = Cmd.mValue->DispatchCuda({{B}, {K}});
        ASSERT_TRUE(Dispatched) << Dispatched.mMessage.c_str();
        FArdaRHITextureSlice Slice; Slice.mMipLevel = 1;
        ASSERT_TRUE(Cmd.mValue->CopyTextureToStaging(*Readback.mValue, Slice, *Texture.mValue, Slice));
        ASSERT_TRUE(Cmd.mValue->Close());
        auto Submitted = mDevice->ExecuteCommandList(Cmd.mValue); ASSERT_TRUE(Submitted) << Submitted.mStatus.mMessage.c_str();
        // The submission must retain the native image, CUDA mapping and executable.
        B.mResource.Reset();
        Texture.mValue.Reset(); Cmd.mValue.Reset();
        ASSERT_TRUE(mDevice->WaitForIdle());
        auto Mapped = mDevice->MapStagingTexture(Readback.mValue, Slice, EArdaRHICpuAccess::Read); ASSERT_TRUE(Mapped);
        for (uint32_t Y = 0; Y < 19; ++Y)
        {
            const auto* Row = reinterpret_cast<const uint32_t*>(static_cast<const uint8_t*>(Mapped.mValue.mData) + Y * Mapped.mValue.mRowPitch);
            for (uint32_t X = 0; X < 27; ++X) EXPECT_EQ(Row[X], Y*27+X+101) << X << "," << Y;
        }
        mDevice->UnmapStagingTexture(Readback.mValue);
    }

Separate source, invocation and selection

A CUDA operand can own reusable CUDA C++ source and select implementations from input dimensions. FArdaCudaModule owns a translation unit, include contents and compiler options; successful PTX compilation is cached per SM architecture. Multiple implementations can retain the same module. Use EArdaCudaSourceLanguage::Ptx for an already compiled module.

FArdaComputeCudaImplementation::mInvoke is the host invocation entry point. It packs resource/scalar arguments and returns ordered FArdaComputeCudaLaunch records referencing module indices and exported kernel symbols. Registration and selection never compile or launch candidate kernels. After selection, the whole launch sequence is checked, only referenced modules compile, and the RHI records the prepared work.

Provide one shape per port in FArdaComputeInvocation::mBindingDimensions. Shapes may have arbitrary rank and are independent of logical extent and GPU tiling. An empty outer vector keeps extent-only calls compatible; an empty inner vector denotes a scalar. Axes must be nonzero. The operand validates rank, matching dimensions, dtype/layout parameters, overflow and storage bounds. An optional registration Supports function filters incompatible shapes before the constructor's FArdaComputeKernelSelector or overridden SelectVariant runs. Pinned variants must pass the same checks.

The compiled example shares this source across small and large implementations, invokes two ordered additions, and selects by the input's column dimension. The GPU test changes shapes from [4, 32] to [1, 128] while keeping extent and element count fixed; it checks the selected implementation, every output value and one shared compilation.

Reusable CUDA C++ translation unit
// One translation unit shared by several shape-specific operand implementations.
#include "ArdaCudaOperandValue.h"

extern "C" __global__ void add_values(const unsigned int* Input, unsigned int* Output,
    unsigned int Count, unsigned int Bias)
{
    const unsigned int Index = blockIdx.x * blockDim.x + threadIdx.x;
    if (Index < Count)
    {
        Output[Index] = AddArdaOperandValue(Input[Index], Bias);
    }
}
Complete dimension-based operand, invocation and selector
size_t SelectArdaAddKernel(const FArdaComputeInvocation& Invocation, const FArdaCudaCapabilities&,
    const eastl::vector<size_t>& Eligible)
{
    const size_t Preferred = Invocation.mBindingDimensions[0][1] <= 64 ? 0 : 1;
    for (const size_t Index : Eligible)
    {
        if (Index == Preferred)
        {
            return Index;
        }
    }
    return Eligible.front();
}

TArdaRHIResult<eastl::vector<FArdaComputeCudaLaunch>> InvokeArdaAddKernel(
    const FArdaComputeInvocation& Invocation, uint32_t BlockSize)
{
    const auto& Dimensions = Invocation.mBindingDimensions[0];
    const uint32_t Count = static_cast<uint32_t>(Dimensions[0] * Dimensions[1]);
    FArdaComputeCudaLaunch First;
    First.mEntryPoint = "add_values";
    First.mBlockSize[0] = BlockSize;
    First.mGridSize[0] = 1 + (Count - 1) / BlockSize;
    First.mArguments = {FArdaCudaArgument::Binding(0), FArdaCudaArgument::Binding(1),
        FArdaCudaArgument::Value(Count), FArdaCudaArgument::Value(7u)};
    auto Second = First;
    Second.mArguments[0] = FArdaCudaArgument::Binding(1);
    Second.mArguments[3] = FArdaCudaArgument::Value(11u);
    return {{First, Second}, {}};
}

class FArdaDimensionAddOperand final : public FArdaComputeOperand
{
public:
    explicit FArdaDimensionAddOperand(eastl::shared_ptr<const FArdaCudaModule> Module,
        FArdaComputeShaderDispatch Fallback = {})
        : FArdaComputeOperand("sample.dimension_add", {
            {"input", EArdaComputeBindingType::Buffer, EArdaComputeAccess::Read, 4, 4},
            {"output", EArdaComputeBindingType::Buffer, EArdaComputeAccess::ReadWrite, 4, 4}},
            SelectArdaAddKernel)
    {
        EXPECT_TRUE(RegisterCuda("cuda.small", 70, UINT32_MAX,
            FArdaComputeCudaImplementation{{Module}, [](const auto& Invocation, const auto&)
            {
                return InvokeArdaAddKernel(Invocation, 32);
            }}, [](const auto& Invocation, const auto&)
            {
                return Invocation.mBindingDimensions[0][1] <= 64;
            }));
        EXPECT_TRUE(RegisterCuda("cuda.large", 70, UINT32_MAX,
            FArdaComputeCudaImplementation{{Module}, [](const auto& Invocation, const auto&)
            {
                return InvokeArdaAddKernel(Invocation, 128);
            }}));
        if (Fallback)
        {
            EXPECT_TRUE(RegisterGraphics("graphics.add", eastl::move(Fallback)));
        }
    }

    FArdaRHIStatus ValidateInvocation(const FArdaComputeInvocation& Invocation) const override
    {
        if (Invocation.mBindingDimensions.size() != 2 || Invocation.mBindingDimensions[0].size() != 2 ||
            Invocation.mBindingDimensions[0] != Invocation.mBindingDimensions[1])
        {
            return FArdaRHIStatus::Error(EArdaRHIResult::InvalidArgument, "Add requires matching rank-two shapes.");
        }
        const auto& Shape = Invocation.mBindingDimensions[0];
        if (Shape[0] > UINT32_MAX / Shape[1])
        {
            return FArdaRHIStatus::Error(EArdaRHIResult::InvalidArgument, "Add element count exceeds its uint32 ABI.");
        }
        for (const auto& Binding : Invocation.mBindings)
        {
            const auto* Buffer = dynamic_cast<IArdaRHIBuffer*>(Binding.mResource.Get());
            if (Binding.mBufferRange.Resolve(Buffer->GetDesc()).mByteSize != Shape[0] * Shape[1] * 4)
            {
                return FArdaRHIStatus::Error(EArdaRHIResult::InvalidArgument, "Add shape does not match the buffer view.");
            }
        }
        return {};
    }
};

Compile CUDA C++ with the optional NVRTC adapter

Configure ARDASHIR_NVRTC_INCLUDE_DIR with a directory containing nvrtc.h, link Ardashir::ArdaCudaCompiler, and call CreateArdaNvrtcCompiler(absoluteLibraryPath). Pass the returned callback to FArdaCudaModule::Create together with the owned source, include contents and options. The adapter targets compute_<SM>, retains the dynamic library and propagates compiler diagnostics. Export kernel symbols with extern "C"; template name lowering and device linking require a custom compiler callback. Target architecture options cannot override the module's requested SM.

Deploy NVRTC and its matching builtins library on the process library search path (PATH on Windows). Set ARDA_TEST_NVRTC_LIBRARY to the absolute library path to enable the compiler and source GPU tests. PTX operands and custom compiler callbacks need no NVRTC build dependency. Missing adapter build support returns Unsupported. The source cache is per immutable module: recreate it when source, external includes, options or compiler policy changes. Native CUDA streams and direct cuBLAS/PyTorch calls are outside this recording interface.

See the module contracts and test instructions and NVIDIA's NVRTC compilation API.

Register one or several kernels

Inherit FArdaComputeOperand. Declare ordered named ports once, including buffer/surface kind, access, minimum buffer size and offset alignment. Optional surface constraints select format/dimension. The base class applies the port access to a copy of each invocation, then validates it before calling either implementation.

The sample registers two ordered CUDA launches with FArdaComputeOperand::RegisterCuda. The first adds 7 to the input; the second adds 11 in place, so the result is input + 18. The builder owns PTX and copied argument bytes. Its SM bounds use major × 10 + minor; SM 12.0 is 120. Register preferred implementations first.

class FAddOperand final : public FArdaComputeOperand
{
public:
    FAddOperand(FArdaComputeShaderDispatch Fallback = {}) : FArdaComputeOperand("sample.add_twice", {
        {"input", EArdaComputeBindingType::Buffer, EArdaComputeAccess::Read, 4, 4},
        {"output", EArdaComputeBindingType::Buffer, EArdaComputeAccess::ReadWrite, 4, 4}})
    {
        EXPECT_TRUE(RegisterCuda("cuda.sequence", 70, UINT32_MAX, [](const FArdaComputeInvocation& I)
            -> TArdaRHIResult<eastl::vector<FArdaCudaKernel>>
        {
            FArdaCudaKernel K;
            K.mPtx = AddPtx; K.mEntryPoint = "add_values";
            K.mBlockSize[0] = 128; K.mGridSize[0] = (I.mExtent[0] + 127) / 128;
            K.mArguments = {FArdaCudaArgument::Binding(0), FArdaCudaArgument::Binding(1),
                FArdaCudaArgument::Value(I.mExtent[0]), FArdaCudaArgument::Value(7u)};
            auto Second = K;
            Second.mArguments[0] = FArdaCudaArgument::Binding(1);
            Second.mArguments[3] = FArdaCudaArgument::Value(11u);
            return {{K, Second}, {}};
        }));
        if (Fallback) EXPECT_TRUE(RegisterGraphics("graphics.add", eastl::move(Fallback)));
    }
    FArdaRHIStatus ValidateInvocation(const FArdaComputeInvocation& I) const override
    {
        for (const auto& B : I.mBindings)
            if (B.mBufferRange.Resolve(dynamic_cast<IArdaRHIBuffer*>(B.mResource.Get())->GetDesc()).mByteSize != uint64_t(I.mExtent[0]) * 4)
                return FArdaRHIStatus::Error(EArdaRHIResult::InvalidArgument, "Add expects one uint32 per element in each view.");
        return {};
    }
};
PTX source used by the operand
const char* AddPtx = R"ptx(.version 8.0
.target sm_70
.address_size 64
.visible .entry add_values(.param .u64 src, .param .u64 dst, .param .u32 count, .param .u32 bias)
{
 .reg .pred p; .reg .b32 r<6>; .reg .b64 a<5>;
 ld.param.u64 a0,[src]; ld.param.u64 a1,[dst]; ld.param.u32 r0,[count]; ld.param.u32 r1,[bias];
 mov.u32 r2,%ctaid.x; mov.u32 r3,%ntid.x; mov.u32 r4,%tid.x;
 mad.lo.u32 r2,r2,r3,r4; setp.ge.u32 p,r2,r0; @p bra done;
 mul.wide.u32 a2,r2,4; add.u64 a3,a0,a2; add.u64 a4,a1,a2;
 ld.global.u32 r5,[a3]; add.u32 r5,r5,r1; st.global.u32 [a4],r5;
done: ret;
})ptx";

The resource parameters are 64-bit binding values; scalar parameters must have exactly the PTX-declared size/layout. Value<T> copies trivially copyable bytes; it does not marshal strings, C++ objects or arbitrary library descriptors.

Record, submit and check results

FArdaComputeInvocation supplies one binding per port, logical extent and application-defined parameter byte arrays. Override ValidateInvocation for exact shape, dtype and parameter schema rules. Generic range checks cannot prove that arbitrary PTX stays inside a buffer.

Dispatch returns the selected variant name or a status. It records work on an open list; Close and ExecuteCommandList submit it. The example uses offset views, non-multiple work sizes and guard bytes, then checks each returned element:

TEST_P(ArdaCudaGpu, OrderedKernelsShareBufferAndPreserveGuardBytes)
{
    const auto C = mDevice->GetCudaCapabilities();
    if (!C) GTEST_SKIP() << C.mUnavailableReason.c_str();
    constexpr uint32_t Count = 1027;
    eastl::vector<uint32_t> Input(Count), Output(Count + 8, 0xdeadbeefu);
    for (uint32_t I = 0; I < Count; ++I) Input[I] = I * 3;
    auto Src = mDevice->CreateBuffer(BufferDesc(Input.size() * 4));
    auto Dst = mDevice->CreateBuffer(BufferDesc(Output.size() * 4));
    ASSERT_TRUE(Src) << Src.mStatus.mMessage.c_str(); ASSERT_TRUE(Dst) << Dst.mStatus.mMessage.c_str();
    EXPECT_EQ(Dst.mValue->GetCudaResourceInfo().mRepresentations, EArdaResourceRepresentations::GraphicsAndCuda);
    auto Cmd = mDevice->CreateCommandList(EArdaRHIQueueType::Graphics); ASSERT_TRUE(Cmd);
    ASSERT_TRUE(Cmd.mValue->Open());
    ASSERT_TRUE(Cmd.mValue->WriteBuffer(*Src.mValue, Input.data(), Input.size()*4, 0));
    ASSERT_TRUE(Cmd.mValue->WriteBuffer(*Dst.mValue, Output.data(), Output.size()*4, 0));
    FArdaComputeInvocation I;
    I.mExtent[0] = Count;
    I.mBindings = {{Src.mValue}, {Dst.mValue}};
    I.mBindings[1].mBufferRange = {16, Count * 4};
    auto Dispatched = FAddOperand().Dispatch(*Cmd.mValue, I, EArdaComputePolicy::RequireCuda);
    ASSERT_TRUE(Dispatched) << Dispatched.mStatus.mMessage.c_str();
    eastl::vector<uint8_t> Readback;
    ASSERT_TRUE(Cmd.mValue->CopyBufferDeviceToHost(*Dst.mValue, Readback));
    ASSERT_TRUE(Cmd.mValue->Close());
    auto Submitted = mDevice->ExecuteCommandList(Cmd.mValue); ASSERT_TRUE(Submitted) << Submitted.mStatus.mMessage.c_str();
    ASSERT_TRUE(mDevice->WaitForIdle());
    ASSERT_EQ(Readback.size(), Output.size()*4);
    std::memcpy(Output.data(), Readback.data(), Readback.size());
    for (uint32_t J = 0; J < Count; ++J) ASSERT_EQ(Output[J+4], Input[J]+18) << "element " << J;
    for (uint32_t J : {0u,1u,2u,3u,Count+4,Count+5,Count+6,Count+7}) EXPECT_EQ(Output[J], 0xdeadbeefu);
    if (C.mLaunchMode == EArdaCudaLaunchMode::D3D12CiG) EXPECT_FALSE(mDevice->ExecuteCommandList(Cmd.mValue));
}

Provide the compute-shader alternative

FArdaComputeOperand::RegisterGraphics stores a callback that creates its binding set, sets resource states, binds a compute pipeline and records Dispatch. The same validated ports/parameters reach the callback. It must implement the same operation semantics as the CUDA sequence.

Without a custom selector, Auto chooses the first eligible registration. RequireGraphics excludes CUDA; RequireCuda excludes graphics. Ordinary nonshared buffers exclude CUDA even on an enabled device. A pinned variant must still satisfy architecture, resource and queue checks. An error after selecting/recording an implementation is propagated: automatic retry could duplicate partially recorded writes.

Complete graphics → CUDA/graphics → graphics example
TEST_P(ArdaCudaGpu, GraphicsFallbackAndMixedShaderCudaSequence)
{
    const auto Path = std::filesystem::path(ARDA_BACKEND_TEST_SHADER_DIR) /
        (std::string("ArdaCudaFallback") + GetShaderArtifactExtension(GetParam()));
    std::ifstream File(Path, std::ios::binary | std::ios::ate);
    ASSERT_TRUE(File);
    eastl::vector<uint8_t> Bytes(static_cast<size_t>(File.tellg()));
    File.seekg(0); File.read(reinterpret_cast<char*>(Bytes.data()), Bytes.size());
    FArdaRHIShaderDesc SD;
    SD.mStage = EArdaRHIShaderStage::Compute; SD.mEntryPoint = "AddFallbackCS";
    SD.mBytecode = Bytes.data(); SD.mBytecodeSize = Bytes.size();
    auto Shader = mDevice->CreateShader(SD); ASSERT_TRUE(Shader);
    FArdaRHIBindingLayoutDesc LD;
    LD.mVisibility = EArdaRHIShaderStage::Compute;
    LD.mItems = {{0, 1, EArdaRHIBindingType::StructuredBufferSRV}, {0, 1, EArdaRHIBindingType::StructuredBufferUAV}};
    auto Layout = mDevice->CreateBindingLayout(LD); ASSERT_TRUE(Layout);
    FArdaRHIComputePipelineDesc PD;
    PD.mComputeShader = Shader.mValue; PD.mBindingLayouts = {Layout.mValue};
    auto Pipeline = mDevice->CreateComputePipeline(PD); ASSERT_TRUE(Pipeline);
    FAddOperand Operand([&](IArdaRHICommandList& Commands, const FArdaComputeInvocation& I)
    {
        FArdaRHIBindingSetDesc BD; BD.mLayout = Layout.mValue;
        for (uint32_t J = 0; J < 2; ++J)
        {
            auto* Buffer = dynamic_cast<IArdaRHIBuffer*>(I.mBindings[J].mResource.Get());

Select variants without mutating live inputs

Override FArdaComputeOperand::SelectVariant to choose an index from the supplied eligible list, using a device/workload tuning cache. The default calls the constructor's selector when supplied, and otherwise preserves registration order. Out-of-set indices are rejected. Benchmark with scratch resources before normal dispatch; selection itself must not launch candidate kernels on live outputs.

Construct and register before publishing the operand. Concurrent Dispatch calls require independently synchronized command lists and thread-safe callbacks. The selection example deliberately rejects duplicate names and an invalid tuning result:

class FSelectionOperand final : public FArdaComputeOperand
{
public:
    bool mbInvalidSelection = false;
    FSelectionOperand() : FArdaComputeOperand("sample.selection", {})
    {
        const auto Graphics = [](IArdaRHICommandList&, const FArdaComputeInvocation&) { return FArdaRHIStatus{}; };
        EXPECT_TRUE(RegisterGraphics("first", Graphics));
        EXPECT_FALSE(RegisterGraphics("first", Graphics));
        EXPECT_FALSE(RegisterGraphics("empty", {}));
        EXPECT_TRUE(RegisterGraphics("tuned", Graphics));
        EXPECT_TRUE(RegisterCuda("unsupported_architecture", UINT32_MAX, UINT32_MAX,
            [](const FArdaComputeInvocation&) -> TArdaRHIResult<eastl::vector<FArdaCudaKernel>>
            {
                ADD_FAILURE() << "Architecture-ineligible builder must never run";
                return {};
            }));
    }
    size_t SelectVariant(const FArdaComputeInvocation&, const FArdaCudaCapabilities&,
        const eastl::vector<size_t>& Eligible) const override
    { return mbInvalidSelection ? SIZE_MAX : Eligible.back(); }
};

Choose native or context-switching execution

Set FArdaBackendConfiguration::mCudaExecutionMode before initialization. Automatic prefers the native graphics-queue path, then selects an ordinary CUDA context when that path is unavailable or D3D12 image qualification fails. GraphicsQueue pins native execution. ContextSwitch forces separate execution on both APIs.

using namespace arda;
FArdaBackendConfiguration Config;
Config.mBackendName = "native-vulkan";
Config.mCudaExecutionMode = EArdaCudaExecutionMode::ContextSwitch;
if (!ConfigureBackend(Config)) return;
if (!InitializeBackend()) return;
const auto Capabilities = GetDevice()->GetCudaCapabilities();
// Existing DispatchCuda calls now record deferred CUDA segments.
// Inspect mLaunchMode, mFallbackReason, and the surface capability flags.

Recording does not execute CUDA. Submission splits mixed command lists at each CUDA dispatch, completes preceding graphics work, executes the CUDA stream to completion, and then resumes graphics. This mode blocks the submitting CPU at each boundary and prevents overlap between Arda graphics and CUDA work. The final graphics segment retains normal RHI fence completion. Recorded arguments, modules and resources remain owned through completion. Reset discards unsubmitted work; submitting the same CUDA recording twice is rejected.

Vulkan fallback requires an enabled OS external-memory extension, dedicated exported memory, a matching CUDA UUID, and ownership release/acquire barriers. The host must serialize access to borrowed queues. CUDA 12.0 headers suffice; missing optional parameter metadata on an older driver leaves PTX argument ABI checking to the kernel author.

Current qualification limit: Vulkan ContextSwitch admits ordinary 1D/2D/3D surfaces but rejects layered surfaces. The layered cross-API readback oracle failed despite successful mapping; mbLayeredSurfaceAccess reports this restriction. D3D12 ordinary-context execution passes all five supported dimensions, including arrays. Native Vulkan kernels retain array support. Use a graphics texture and explicit graphics operand alternative when sharing is not qualified.

Native execution and lifetime limits

D3D12: the provider matches the adapter LUID and CUDA device, creates a CiG context on the graphics queue, imports shared committed memory and captures kernels with cuStreamBeginCaptureToCig/cuStreamEndCaptureToCig. UAV barriers surround capture. Streams, mappings and executable modules are retained until graphics-fence retirement. Submit or discard a captured list before recording another on the same context; captured lists are single-use.

Vulkan: VK_NV_cuda_kernel_launch records kernels directly on a graphics/compute command buffer. Buffer device addresses are used only by this native launch path; they are not advertised as arbitrary CUDA-runtime pointers. VK_NVX_image_view_handle supplies 64-bit storage-image surface handles. Memory barriers order kernels and graphics consumers, and existing submission retention owns resources/modules until completion. Copy queues are unsupported.

The shared CUDA driver bridge checks kernel parameter metadata when the driver exposes that query; older drivers leave custom PTX argument ABI validation to the caller. This Vulkan path has no equivalent parameter-metadata query; custom PTX authors remain responsible for matching argument ABI. Both providers validate declared ranges, dimensions and launch limits.

Verified support and failure diagnosis

Qualification used Windows, RTX PRO 6000 Blackwell (SM 120), driver 610.62 / CUDA driver 13.3 and CUDA 13.3.29 headers. Buffer kernels and mixed graphics/CUDA work passed on both APIs. Native Vulkan surface reads/writes passed all 24 formats × 5 dimensions, plus nonuniform 2D addressing and allocation variations.

D3D12 CiG surfaces are unavailable on this tested driver: image import succeeds but mapping to a mipmapped array fails in a CiG context. The provider probes this. Automatic mode selects an ordinary CUDA context; explicitly pinned GraphicsQueue mode disables surface admission with a reason. Forced native D3D12 CiG image execution remains unqualified; ordinary D3D12 context surfaces passed the format and dimension matrix. Those historical results cover native queue execution. The context-switching tests additionally verify ordinary streams, discard, replay rejection, and mixed submission on this Windows GPU; a full build against official CUDA 12.0 headers also passed the available focused GPU tests on this driver. Older installed drivers and other OS/GPU combinations remain unqualified.
