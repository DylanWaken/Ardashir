How to read this reference

Namespaces

Lifecycle, shaders, pipelines, logging, and presentation live in arda::backend. Backend-neutral GPU types and interfaces live in arda::rhi. Qualified names show the owning namespace or type; short names are convenient search terms but may match overloads or members in several types.

Status and result conventions

A bool result reports whether an operation was accepted or completed according to its contract; read the Returns and Errors rows for the precise meaning. Result and status enums carry richer outcomes where a binary answer is insufficient. A successful call can still require later GPU synchronization, so success does not imply that queued work has finished.

Ownership and threading notation

The Ownership row says whether an argument is borrowed, copied, retained, transferred, or returned through an intrusive reference. “Caller-owned” means the caller must preserve the object for the stated lifetime. The Threading row distinguishes externally serialized process-wide operations, thread-safe APIs, recording-thread restrictions, and GPU ordering requirements. These contracts are part of the API, not optional guidance.

Descriptor naming

Types named *Desc, *Descriptor, *CreateInfo, or *Initializer collect configuration rather than representing a live GPU object. Their member-variable entries document defaults, validity, and relationships. Resource and state objects created from them can have different ownership and synchronization rules.

Signatures and entries

Each entry begins with its qualified symbol name and declaration. Parameter rows describe individual inputs when source documentation provides them. Returns, Ownership, Errors, Threading, Source, and Audience appear only when recorded. Overloads have separate stable IDs even when their qualified names are identical.
