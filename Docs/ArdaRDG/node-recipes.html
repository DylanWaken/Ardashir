Self-contained node recipes

Register compute, CUDA, ray-tracing, mesh, raster, and work-graph nodes and run the compiled examples.

Learning objectives and prerequisites

After this chapter you can write a node library, assemble its operations without native binding setup, predict when resources create dependencies, and diagnose pipeline or descriptor errors. Read edit transactions, parameter snapshots and logical versus physical resources first. The examples require an initialized RHI device, supported GPU features and shader compilation or deployed shader artifacts.

Record operations on resource variables

Begin an FArdaGraphEdit, call operations on typed buffer and texture variables, then check Edit.Commit() and Graph.CompileAndWait(). Publish a named global callable after each node class with ARDA_DECLARE_GRAPH_NODE(FArdaMyNode, MyOperation) and define it once in the implementation with ARDA_DEFINE_GRAPH_NODE(FArdaMyNode, MyOperation). Call MyOperation(Edit, Parameters) or MyOperation(Edit, Input, Output, Value). Positional arguments initialize the node's parameter fields in declaration order. Calls return typed outputs through GetBuffer and GetTexture. Retrieve outputs before committing, retain terminal resources with Edit.Keep, and call Readback for CPU results. The facade automatically registers nodes and records their dependencies. Calls such as CopyTo(Edit, Source, Destination) select the appropriate node from the resource types.

The edit retains the first authoring error and stops later mutations. A failed commit leaves the transaction open for rollback; Cancel() or scope destruction discards it. A successful commit queues the edit. Graph.CompileAndWait() selects or compiles a persistent revision, and Graph.ExecuteAndWait() runs it. Multiple committed edits can share resource variables within one construction. The next ordinary edit after execution starts empty; describe the next frame again to reuse a matching cached revision without removing old nodes.

A shader argument is a reference to a logical value before it is a GPU descriptor. A node describes what it reads and produces; an edge constrains when a value becomes available. Separating those facts from physical addresses lets the compiler schedule work and choose allocations before building descriptors. Putting allocation or descriptor creation in every recording callback would prevent that separation and repeat CPU work during replay.

The common TArdaNodeDefinition template supplies static invocation, registration and preparation lifetime. Its EArdaNodeType selector fixes the execution contract, while the compiler chooses the native queue. Declare parameters with ARDA_BEGIN_NODE_PARAMETER_STRUCT; field metadata supplies dependencies and canonical identity. Custom hooks add preparation, pipeline requests and recording. A class can use inherited stateless hooks when it needs no setup.

  1. Override static GetRequirements for hardware or library prerequisites. The graph checks explicit needs before output declaration, validation and preparation, and checks recognizable descriptor needs after Describe. See the compiled hook examples; unsupported attachment returns a named diagnostic without inserting the node.
  2. In DeclareResources, declare named outputs through FArdaDependencyResourceContext. An empty handle creates a graph-owned logical resource; a supplied handle is checked against the output requirements. Failed attachment rolls back newly declared outputs.
  3. The base computes canonical identity after output resolution. Include every behavior-affecting field in the key. Every callable or static invocation creates a fresh operation with an automatic name. An optional diagnostic name must be unique. Every invocation creates a new operation; equivalent complete constructions are reused by the revision cache.
  4. Prepare loads the node's shaders and immutable configuration. The base's weak cache shares live state for the same node type and device. Resource-dependent instance setup is separate.
  5. ARDA_NODE_SHADER_* fields map graph resources to the canonical shader schema, inheriting binding types and access requirements. CUDA fields use ARDA_NODE_CUDA_*; attachment and non-shader resource fields declare their corresponding accesses. Optional Describe returns FArdaDependencyNodeDesc with prepared stages, pipeline requests, frozen push-constant bytes and dynamic requirements. It does not repeat static resource declarations. Stage identity, stage inputs and the stage-only scheduling flag are compiler-owned; Describe must leave those fields at their defaults.
  6. Edit.Commit() queues a hashed edit. Graph.CompileAndWait() reuses a cached construction or resolves resource edges, schedules work, infers pipeline patterns and publishes a memory plan. The first Submit allocates storage and prepares PSOs, fixed bindings, bindless tables, parameter relocations and ray tables for each frame slot.
  7. Record calls the context's state helper and supplies draw or dispatch arguments. FArdaDependencyExecutionContext supplies the prepared PSO, framebuffer, bindings, parameters and shader table. Ordinary replay reuses them.

Publish each class with ARDA_DECLARE_GRAPH_NODE(NodeClass, InvocationName); immediately after its declaration, and the matching ARDA_DEFINE_GRAPH_NODE once in its implementation. Declaration automatically registers the type for discovery and deserialization. Call InvocationName(Edit, Parameters) or pass positional fields to record an operation. NodeClass::Register() remains idempotent. The registration walkthrough covers the complete header and implementation contract. Overloaded free functions can delegate to these callables, keeping validation and dependencies in the node definition. Registry-driven tools can use Edit.Invoke(DefinitionName, Parameters) after registration. Device setup occurs during invocation, not global registry discovery. Compile results retain prepared node state and descriptions; compiled frames retain physical objects until GPU retirement. Keep a graph across frames. Changing shapes, resource identities or frozen values requires an edit; changing synchronized external input contents does not.

Build the native shader recipes

ArdaGraphTests compiles the compute, mesh, raster, and work-graph recipes. To use them in your application, link Ardashir::ArdaDependencyGraph and compile the four node implementation files with AssembleNodes.cpp. That assembly defines RegisterRecipeLibrary to register all four recipes. To use one recipe, compile its node implementation and copy the corresponding assembly function.

Make RecipeNodeSupport.h available to the implementation and define ARDA_RDG_RECIPE_SHADER_DIR as the absolute path to Docs/ArdaRDG/Examples/Nodes/Shaders. Turn on on-demand compilation in development or deploy matching shader artifacts for load-only mode.

Compute shader

One dispatch writes the frozen value 123 to a graph-owned four-byte buffer. A separate readback node makes the result observable. The shader parameter struct declares both the push constant and UAV; the graph supplies their native bindings.

Call FArdaComputeWriteNode::Register() for explicit discovery. The assembly dispatches the shader and checks the readback after each execution. ComputeWrite shader source

FArdaRHIStatus RunComputeRecipe(FArdaRHIDeviceRef Device)
{

	// Readback retains the producer chain and publishes its result after execution.
	FArdaDependencyGraph Graph(Device);
	FArdaGraphEdit Edit(Graph);
	const auto Compute = ComputeWrite(Edit, {{}, 123}).GetBuffer("Output");
	const auto Bytes = Readback(Edit, Compute);

	// Queue this construction, then select or compile its persistent revision.
	if (auto S = Edit.Commit(); !S)
	{
		return S;
	}
	if (auto S = Graph.CompileAndWait(); !S)
	{
		return S;
	}

	// Replay the same compiled graph across frames.
	for (unsigned Frame = 0; Frame < 3; ++Frame)
	{
		const auto Run = Graph.ExecuteAndWait();
		if (!Run.mStatus)
		{
			return Run.mStatus;
		}

		// The synchronous convenience call completed the readback; validate the observable result.
		uint32_t Value = 0;
		if (Bytes->size() != sizeof(Value))
		{
			return FArdaRHIStatus::Error(EArdaRHIResult::InvalidState, "Unexpected readback size.");
		}
		std::memcpy(&Value, Bytes->data(), sizeof(Value));
		if (Value != 123)
		{
			return FArdaRHIStatus::Error(EArdaRHIResult::InvalidState, "Unexpected compute-graph output.");
		}
	}
	return {};
}

Mesh shader / meshlet pipeline

The node privately registers mesh and pixel shaders, declares an offscreen color output, supplies raster state and requests a Meshlet pipeline. Two instances retain different output textures but share one matching PSO. The GPU test checks creation and replay; it does not compare rendered pixels.

Call FArdaMeshTriangleNode::Register() for explicit discovery. The assembly creates both offscreen draws in one edit. MeshTriangle shader source

FArdaRHIStatus RunMeshRecipe(FArdaRHIDeviceRef Device)
{

	// Each invocation records an operation and returns its typed resources.
	FArdaDependencyGraph Graph(Device);
	FArdaGraphEdit Edit(Graph);
	const auto First = MeshTriangle(Edit, {}).GetTexture("Color");
	const auto Second = MeshTriangle(Edit, {}).GetTexture("Color");
	Edit.Keep(First);
	Edit.Keep(Second);

	// Queue this construction, then select or compile its persistent revision.
	if (auto S = Edit.Commit(); !S)
	{
		return S;
	}
	if (auto S = Graph.CompileAndWait(); !S)
	{
		return S;
	}
	// Compilation retains pipeline patterns without creating native PSOs.
	const auto Compiled = Graph.GetPipelineCacheStats();
	if (Compiled.mMeshletEntries != 0 || Compiled.mHits != 0 || Compiled.mMisses != 0)
	{
		return FArdaRHIStatus::Error(EArdaRHIResult::InvalidState, "Compilation created a native mesh PSO.");
	}
	if (const auto FirstRun = Graph.ExecuteAndWait(); !FirstRun.mStatus)
	{
		return FirstRun.mStatus;
	}
	// First submission prepares both instances and reuses their matching mesh PSO.
	const auto Prepared = Graph.GetPipelineCacheStats();
	if (Prepared.mMeshletEntries != 1 || Prepared.mHits < 1 || Prepared.mMisses != 1)
	{
		return FArdaRHIStatus::Error(EArdaRHIResult::InvalidState, "Expected mesh PSO reuse.");
	}

	// Later frames reuse the prepared objects without further cache requests.
	for (unsigned Frame = 1; Frame < 3; ++Frame)
	{
		const auto Run = Graph.ExecuteAndWait();
		if (!Run.mStatus)
		{
			return Run.mStatus;
		}
		const auto Replayed = Graph.GetPipelineCacheStats();
		if (Replayed.mMeshletEntries != Prepared.mMeshletEntries || Replayed.mHits != Prepared.mHits ||
		    Replayed.mMisses != Prepared.mMisses)
		{
			return FArdaRHIStatus::Error(EArdaRHIResult::InvalidState,
			    "Mesh replay changed pipeline cache activity.");
		}
	}
	return {}; // These offscreen textures are released with Graph. Retain Graph in a renderer.
}

	TArdaRHIResult<eastl::shared_ptr<const FArdaMeshTriangleNode::FArdaState>> FArdaMeshTriangleNode::Prepare(
	    FArdaRHIDeviceRef Device)
	{
		if (!Device)
		{
			return {{}, FArdaRHIStatus::Error(EArdaRHIResult::InvalidState, "Mesh preparation needs a device.")};
		}

		auto State = eastl::make_shared<FArdaState>();
		if (!State->mShaders.Initialize(Device))
		{
			return {{}, ShaderError(State->mShaders)};
		}

		const auto* Mesh = State->mShaders.Find(FArdaRecipeMeshShader::GetStaticType());
		const auto* Pixel = State->mShaders.Find(FArdaRecipePixelShader::GetStaticType());
		if (!Mesh || !Pixel)
		{
			return {{}, ShaderError(State->mShaders)};
		}
		for (const auto* Shader : {Mesh, Pixel})
		{
			FArdaInductorPipelineContribution Stage;
			Stage.mShader = Shader->GetShader();
			State->mStages.push_back(eastl::move(Stage));
		}
		auto Config = eastl::make_shared<FArdaInductorPipelineConfiguration>();
		Config->mKind = EArdaPipelineStateKind::Meshlet;
		auto& Desc = Config->mMeshlet.mDesc;
		Desc.mRasterState.mCullMode = EArdaRHICullMode::None;
		Desc.mDepthStencilState.mbDepthTest = false;
		Desc.mDepthStencilState.mbDepthWrite = false;
		Desc.mSampleCount = 0; // ArdaInductor completes formats and samples from the framebuffer.
		State->mConfiguration = eastl::move(Config);
		return {eastl::move(State), {}};
	}

	FArdaDependencyNodeDesc FArdaMeshTriangleNode::Describe(const FArdaParameters& P, const FArdaState& State)

		FArdaDependencyNodeDesc D;

	FArdaRHIStatus FArdaMeshTriangleNode::Record(FArdaDependencyExecutionContext& C,
	    const FArdaParameters& P,
	    const FArdaState&,
	    FArdaInstanceState&)
	{
		auto Color = C.GetTexture(P.mColor);
		if (auto S = C.GetCommands().ClearTexture(*Color, {}, {0.f, 0.f, 0.f, 1.f}); !S)
		{
			return S;
		}
		FArdaRHIMeshletState State;
		State.mViewports = {{0.f, float(P.mWidth), 0.f, float(P.mHeight), 0.f, 1.f}};
		State.mScissors = {{0, int32_t(P.mWidth), 0, int32_t(P.mHeight)}};
		if (auto S = C.SetMeshletState(State); !S)
		{
			return S;
		}

		return C.GetCommands().DispatchMesh(1, 1, 1);
	}

Rasterization

This vertex-ID triangle uses separate vertex, raster and pixel node classes. Typed vertex and fragment variables connect the stages automatically. The same vertex result feeds two raster operations, creating two independent draws that execute the vertex shader twice and reuse one compatible graphics PSO. Geometry uploads can supply declared vertex/index reads as shown by RHITest. FetchBuffer(Edit, Vertices) explicitly runs a compute materializer sharing the VS position function; the recipe verifies its float4 position records by GPU readback.

Register the vertex, raster, and pixel classes for explicit discovery. The assembly records a shared vertex stage, two raster operations, and a readback. RasterTriangle shader source

FArdaRHIStatus RunRasterRecipe(FArdaRHIDeviceRef Device)
{

	// Each invocation records an operation and returns its typed resources.
	FArdaDependencyGraph Graph(Device);
	FArdaGraphEdit Edit(Graph);
	FArdaRHITextureDesc TargetDesc;
	TargetDesc.mWidth = 64;
	TargetDesc.mHeight = 64;
	TargetDesc.mFormat = EArdaRHIFormat::RGBA8UNorm;
	TargetDesc.mUsage = EArdaRHITextureUsage::RenderTarget;
	const auto First = AllocateTexture(Edit, TargetDesc);
	const auto Second = AllocateTexture(Edit, TargetDesc);
	const auto Vertices = RecipeTriangleVS(Edit, uint32_t{3});
	const auto Positions = Readback(Edit, FetchBuffer(Edit, Vertices));
	const auto FirstFragments = RecipeTriangleRasterize(Edit, Vertices, uint32_t{64}, uint32_t{64});
	const auto SecondFragments = RecipeTriangleRasterize(Edit, Vertices, uint32_t{64}, uint32_t{64});
	RecipeTrianglePS(Edit, FirstFragments, First);
	RecipeTrianglePS(Edit, SecondFragments, Second);
	// Each raster branch becomes a separate draw, including its own vertex execution.
	Edit.Keep(First);
	Edit.Keep(Second);

	// Queue this construction, then select or compile its persistent revision.
	if (auto S = Edit.Commit(); !S)
	{
		return S;
	}
	if (auto S = Graph.CompileAndWait(); !S)
	{
		return S;
	}
	// Compilation retains pipeline patterns without creating native PSOs.
	const auto Compiled = Graph.GetPipelineCacheStats();
	if (Compiled.mGraphicsEntries != 0 || Compiled.mComputeEntries != 0 || Compiled.mHits != 0 ||
	    Compiled.mMisses != 0)
	{
		return FArdaRHIStatus::Error(EArdaRHIResult::InvalidState, "Compilation created a native raster PSO.");
	}
	if (const auto FirstRun = Graph.ExecuteAndWait(); !FirstRun.mStatus)
	{
		return FirstRun.mStatus;
	}
	// First submission prepares both instances and reuses their matching graphics PSO.
	const auto Prepared = Graph.GetPipelineCacheStats();
	if (Prepared.mGraphicsEntries != 1 || Prepared.mComputeEntries != 1 || Prepared.mHits < 1 ||
	    Prepared.mMisses != 2)
	{
		return FArdaRHIStatus::Error(EArdaRHIResult::InvalidState, "Expected raster PSO reuse.");
	}
	// The explicit materializer evaluates the same position function as the vertex shader.
	const float ExpectedPositions[12] = {-1.f, -1.f, 0.f, 1.f, -1.f, 3.f, 0.f, 1.f, 3.f, -1.f, 0.f, 1.f};
	if (Positions->size() != sizeof(ExpectedPositions) ||
	    std::memcmp(Positions->data(), ExpectedPositions, sizeof(ExpectedPositions)) != 0)
	{
		return FArdaRHIStatus::Error(EArdaRHIResult::InvalidState,
		    "Vertex materialization returned unexpected positions.");
	}

	// Later frames reuse the prepared objects without further cache requests.
	for (unsigned Frame = 1; Frame < 3; ++Frame)
	{
		const auto Run = Graph.ExecuteAndWait();
		if (!Run.mStatus)
		{
			return Run.mStatus;
		}
		const auto Replayed = Graph.GetPipelineCacheStats();
		if (Replayed.mGraphicsEntries != Prepared.mGraphicsEntries ||
		    Replayed.mComputeEntries != Prepared.mComputeEntries || Replayed.mHits != Prepared.mHits ||
		    Replayed.mMisses != Prepared.mMisses)
		{
			return FArdaRHIStatus::Error(EArdaRHIResult::InvalidState,
			    "Raster replay changed pipeline cache activity.");
		}
	}
	return {}; // These offscreen textures are released with Graph. Retain Graph in a renderer.
}

A CPU entry record drives one work-graph node that writes 123. Global resource bindings are generated from the shader struct. The RHI creates program backing storage. Entry records supply scalar inputs: global graph push-constant arguments are rejected for work graphs. D3D12 requires work-graph support; the current Vulkan backend returns Unsupported.

Call FArdaWorkWriteNode::Register() for explicit discovery. The assembly supplies the entry record and checks the resulting buffer. WorkWrite shader source

FArdaRHIStatus RunWorkRecipe(FArdaRHIDeviceRef Device)
{

	// Readback retains the producer chain and publishes its result after execution.
	FArdaDependencyGraph Graph(Device);
	FArdaGraphEdit Edit(Graph);
	const auto Work = WorkWrite(Edit, {{}, 123}).GetBuffer("Output");
	const auto Bytes = Readback(Edit, Work);

	// Queue this construction, then select or compile its persistent revision.
	if (auto S = Edit.Commit(); !S)
	{
		return S;
	}
	if (auto S = Graph.CompileAndWait(); !S)
	{
		return S;
	}

	// Replay the same compiled graph across frames.
	for (unsigned Frame = 0; Frame < 3; ++Frame)
	{
		const auto Run = Graph.ExecuteAndWait();
		if (!Run.mStatus)
		{
			return Run.mStatus;
		}

		// The synchronous convenience call completed the readback; validate the observable result.
		uint32_t Value = 0;
		if (Bytes->size() != sizeof(Value))
		{
			return FArdaRHIStatus::Error(EArdaRHIResult::InvalidState, "Unexpected readback size.");
		}
		std::memcpy(&Value, Bytes->data(), sizeof(Value));
		if (Value != 123)
		{
			return FArdaRHIStatus::Error(EArdaRHIResult::InvalidState, "Unexpected work-graph output.");
		}
	}
	return {};
}

Each record's mRecordIndex is dense and zero-based within its category: raygen 0, miss 0, hit-group 0 are three different valid records. The graph converts them to the RHI's flat record array. Per-record mLocalBindings can declare metadata and logical resource arguments. First-submission preparation creates the local binding set for each frame slot. Raw local argument bytes use mLocalArguments. Native limits still apply: D3D12 supports these fixed local layouts; the current Vulkan backend requires direct-heap local descriptors and rejects this fixed-local-binding path. Bindless indices are addresses, not dependencies

A descriptor index selects a view. Two different indices may alias the same bytes, and two views of the same buffer may cover disjoint bytes. The compiler therefore resolves FArdaDependencyBindlessTable entries to resource identity and view ranges before creating dependency edges. Tables are immutable and node-local: different nodes can populate different entries of the same compatible layout. A zero capacity selects one past the greatest populated index, within the declared maximum.

// Inside Describe; P.mBuffer is a shared 256-byte logical buffer.
FArdaDependencyBindlessTable T;
T.mName = "tiles";
T.mCapacity = 2;
T.mLayout.mVisibility = EArdaRHIShaderStage::Compute;
T.mLayout.mRegisterSpace = 0;
T.mLayout.mMaxCapacity = 2;
T.mLayout.mRegisterSpaces = {{0, 2, EArdaRHIBindingType::StructuredBufferUAV}};
FArdaDependencyBindlessEntry E;
E.mArrayElement = P.mDescriptorIndex;
E.mType = EArdaRHIBindingType::StructuredBufferUAV;
E.mResource = P.mBuffer;
E.mView.mBufferRange = {P.mByteOffset, 128};
E.mAccess = EArdaDependencyAccess::Write;
T.mEntries = {E};
D.mBindlessTables = {T};
// A: index 0, offset 0. B: index 1, offset 128.
// Both can request the same compute shader and pipeline configuration.

For buffer intervals A=[0,128) and B=[128,256), the intersection is empty, so neither writer depends on the other. A whole-buffer reader depends on both; a reader of B depends only on B. A later frame can omit A and the consumers that need A's bytes while recording B and its consumers. Keeping a reader of A's uninitialized bytes would fail compilation. Changing B to [64,192) creates a region [64,128) with repeated writes. Its overlapping writers and readers follow original successful attachment order; the portions written by only one node retain attachment-independent producer-to-reader ordering. A whole-buffer read still needs coverage beyond byte 192. Texture views use the product of mip, array-slice and plane ranges; arbitrary pixel rectangles are not tracked. See the repeated-write example.

Declare every entry a shader might select, including GPU-selected indices. Use an unrestricted resource view when the accessed range is unknown. Sparse holes must never be indexed. An SRV cannot be declared as a writer. A descriptor table is not itself a data dependency: its populated entries supply those dependencies. Undeclared shader access is outside the graph contract.

To supply an index through shader parameters, put a FArdaDependencyDescriptorIndex relocation in a named FArdaDependencyShaderValue. Identify the table, slot, type and populated array element, plus the byte offset of a uint32 field in that value's bytes. First-submission preparation patches the field after table allocation and the state helper applies the prepared push constants. Ordinary indices are table-relative; absolute heap indices require a direct-heap table with exactly one descriptor bank. Attachment validates the table declaration and shader schema; first-submission preparation checks relocation bounds/alignment, referenced entries and absolute-index requirements before patching. Check status at both boundaries.

Independence permits scheduling freedom; it does not guarantee simultaneous GPU occupancy. The executor omits same-state buffer UAV barriers between disjoint ranges while tracking every outstanding unsynchronized access. The RHI still tracks buffer state and queue ownership for the whole buffer, so cross-queue ownership or state changes can impose waits even for disjoint bytes. Separate buffers offer more freedom across queues. Textures track native subresources. Explicit edges, memory-budget ordering and the single CUDA stream can also serialize otherwise independent work.

The compiler compares relevant writer ranges per resource, then validates read coverage: buffer intervals are sorted and merged, and texture coverage is checked over mip/slice/plane cells. Graph-owned reads require complete initialized coverage, possibly from several disjoint producers; imported resources may provide initial contents. Range granularity reduces false edges at the cost of compilation work proportional to access counts and texture subresource cells. Descriptor population is first-submission preparation work: the current RHI writes table entries individually. Measure logical compilation, first-submission preparation and steady-state replay separately for large tables.

The bindless GPU conformance test exercises two disjoint UAV views, relocated indices, numerical readback, PSO sharing and repeated table reuse on D3D12 and Vulkan.

Automatic assignment and stable reuse

Graphics stage templates establish pipeline membership with typed intermediate values. Each pixel terminal selects its raster input and that raster operation's vertex input; unrelated resource dependencies do not select shaders. Other pipeline requests identify a family and a local slot and use only that operation's own contributions and fixed settings. Resource and explicit ordering edges never add shaders to a pipeline. Shader-stage resource accesses and bindings belong in their declarative node parameter schemas.

The raster recipe passes one FArdaGraphVertices value to two raster operations and passes each resulting FArdaGraphFragments value to a pixel operation. Preprocessing assembles two draws and merges the participating stages' bindings and resource accesses. The shared vertex stage executes once per draw. Matching attachment formats and fixed state let the draws reuse one native PSO. The mesh recipe continues to declare one complete mesh pipeline per operation.

The stable key serializes shader content identities, layout semantics, fixed/program state, ray exports and attachment formats deterministically. It excludes node IDs, debug names, slot/group labels and resource addresses. Generated layouts are interned by the graph. The native in-memory cache also verifies shader/layout object compatibility; a matching hash alone does not authorize reuse. Keeping shader objects in shared node preparation state supports reuse across instances. Replacing RGBA8 with another attachment format, changing blend state or changing shader content creates a different pattern.

Multiple named contribution groups require a selected request group; an ungrouped contribution is shared. Conflicting shaders for one stage/export fail rather than selecting an ancestor by distance or attachment order. See the complete inference rules and the compiler chapter for normalization and boundary behavior.

Registration and compilation failures

  • Missing shader member or wrong descriptor type: attachment or compilation reports an argument/layout error. Supply every resource leaf and array element exactly once, using the shader's metadata, and match push-constant byte sizes.
  • Hidden allocation or descriptor mutation in Record: the compiler cannot account for hidden hazards and replay may use stale bindings. Declare outputs and tables before compilation; keep opaque library workspace in the node's workspace estimate and declare all its data access.
  • Repeated writes: on regions with multiple distinct writer nodes, attach writes and intervening reads in the intended order. Reads consume the preceding writer; an owned read before the first write fails, while imported storage may supply initial contents. ReadWrite needs incoming initialized coverage. Finding a node does not reorder it, and an explicit dependency cannot oppose inferred hazards. Repeated writes reuse one resource; declare separate output handles if older contents must remain available.
  • Incorrect bindless independence: different indices that resolve to overlapping storage still conflict. Narrow a view only when the shader actually stays inside it; shader control flow is not analyzed. Indexing a hole or undeclared resource cannot be made safe by scheduling.
  • Ambiguous pipeline or missing stage: correct the contribution dependencies, select a group or split conflicting consumers. Graphics stage templates declare resource accesses and bindings on their respective stages; preprocessing validates their typed value chain before assembling a draw.
  • Invalid ray table: supply exactly one selected raygen, known exports with the right category and dense category-relative indices. Declare required local arguments explicitly; respect backend local-binding support.
  • Duplicate operation names: explicit diagnostic names must be unique within one construction, even when parameters match. Omit the name to generate a fresh identity, or supply distinct names for repeated calls. Record changed operations in the next frame's empty construction. To replace an unfinished construction, cancel an open edit, discard pending closed edits with DiscardPendingEdits(), and record the corrected operations. Include resources, dimensions, shader choices and frozen parameters in canonical keys. Do not mutate an aliased configuration after attachment.
  • Unsupported hardware or artifacts: check the returned status and device capabilities. Work graphs require D3D12; CUDA must be enabled and its interop path supported. On-demand shader loading needs source directories; load-only needs deployed matching artifacts.

A failed Edit.Commit() leaves that edit open for cancellation; the edit retains its first authoring error, so cancel it and record a corrected edit. A failed Graph.CompileAndWait() retains the queue of closed edits: add missing operations in another edit, or call DiscardPendingEdits() and record a corrected construction before compiling again. Inspect the graph's diagnostic exports and enable native GPU validation while debugging descriptor or synchronization problems. A successful topology check alone does not validate shader indexing behavior.

Summary and checkpoints

Node classes own operation definitions; the graph owns physical preparation. Resource views determine scheduling dependencies, typed stage values determine composed pipeline membership, and normalized state determines reuse. Replay uses retained per-frame objects, while edits rebuild changed semantics.

  1. Why can descriptor indices 3 and 7 still conflict? Resolve their views before comparing ranges.
  2. What changes when a reader covers both halves of a shared output? It joins both producers and must have complete coverage.
  3. Why can two independent buffer ranges still wait across queues? Buffer state and ownership are native whole-object constraints.
  4. When do two draws reuse a pipeline? Their complete normalized state and retained native shader/layout objects must be compatible.
  5. Where is a missing ray-local resource supplied? In an explicit shader-table record declaration before compilation.
