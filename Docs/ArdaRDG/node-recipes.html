Self-contained node recipes

Register compute, CUDA, ray tracing, mesh, rasterization and work-graph operations. Let compilation prepare their resources, bindings, descriptor indices and shader tables.

Learning objectives and prerequisites

After this chapter you can write a node library, assemble its operations without native binding setup, predict when resources create dependencies, and diagnose pipeline or descriptor errors. Read edit transactions, parameter snapshots and logical versus physical resources first. The examples require an initialized RHI device, supported GPU features and shader compilation or deployed shader artifacts.

The compiler owns physical preparation

A shader argument is a reference to a logical value before it is a GPU descriptor. A node describes what it reads and produces; an edge constrains when a value becomes available. Separating those facts from physical addresses lets the compiler schedule work and choose allocations before building descriptors. Putting allocation or descriptor creation in every recording callback would prevent that separation and repeat CPU work during replay.

The common TArdaDependencyNode base supplies registration, attachment and preparation lifetime. Domain specializations fix the operation's execution domain, while the compiler still chooses its native queue. Implement metadata, semantic identity, resource declarations, description and recording in each node's files. A class can use inherited stateless hooks when it needs no setup.

  1. Override static GetRequirements for hardware or library prerequisites. The graph checks explicit needs before output declaration, validation and preparation, and checks recognizable descriptor needs after Describe. See the compiled hook examples; unsupported attachment returns a named diagnostic without inserting the node.
  2. In DeclareResources, declare named outputs through FArdaDependencyResourceContext. An empty handle creates a graph-owned logical resource; a supplied handle is checked against the output requirements. Failed attachment rolls back newly declared outputs.
  3. The base computes canonical identity after output resolution. Include every behavior-affecting field in the key. Matching reattachment returns the existing instance; a name collision with different semantics fails.
  4. Prepare loads the node's shaders and immutable configuration. The base's weak cache shares live state for the same node type and device. Resource-dependent instance setup is separate.
  5. Describe returns FArdaDependencyNodeDesc. Use BindShader<Shader::FArdaParameters> to map named metadata leaves to graph resources and frozen push-constant bytes. Shader metadata generates layouts and accesses. Declare copy, framebuffer and external-library accesses explicitly.
  6. EndGraphEdit resolves resource edges, schedules and allocates, infers PSOs, then prepares fixed bindings, bindless tables, parameter relocations and ray tables separately for each compiled frame slot.
  7. Record calls the context's state helper and supplies draw or dispatch arguments. FArdaDependencyExecutionContext supplies the prepared PSO, framebuffer, bindings, parameters and shader table. Ordinary replay reuses them.

Publish classes by calling MyNode::Register() before discovery, or just use typed Graph.AttachOrFind<MyNode>, which registers on demand. Device setup occurs at attachment, not global registry discovery. Graph parameters retain prepared state; compiled frames retain physical objects until GPU retirement. Keep a graph across frames. Changing shapes, resource identities or frozen values requires an edit; changing synchronized external input contents does not.

Compute shader

One dispatch writes the frozen value 123 to a graph-owned four-byte buffer. A separate readback node makes the result observable. The shader parameter struct declares both the push constant and UAV; the graph supplies their native bindings.

These are compiled recipe sources, built into ArdaGraphTests. In an application, compile all four node .cpp files and the assembly file (it defines all four recipes and the shared registration function), or extract only the assembly function for your selected node, include the private recipe support header, link Ardashir::ArdaRenderGraph, and define ARDA_RDG_RECIPE_SHADER_DIR as an absolute path to the shader directory. Enable on-demand compilation for development, or deploy matching artifacts for load-only mode.

Registration: FArdaComputeWriteNode::Register() publishes the type; RegisterRecipeLibrary registers all four native recipes together. The renderer only attaches operations and wires their output handles:

FArdaRHIStatus RunComputeRecipe(FArdaRHIDeviceRef Device)
	{
		FArdaDependencyGraph Graph(Device);
		if (auto S = Graph.BeginGraphEdit(); !S)
		{
			return S;
		}
		auto Compute = Graph.AttachOrFind<FArdaComputeWriteNode>("write", {{}, 123});
		if (!Compute)
		{
			return Compute.mStatus;
		}
		auto Bytes = eastl::make_shared<eastl::vector<uint8_t>>();
		auto Read =
		    Graph.AttachOrFind<FArdaGraphReadbackNode>("read", {Graph.FindOutput(Compute.mValue, "Output"), Bytes});
		if (!Read)
		{
			return Read.mStatus;
		}
		if (auto S = Graph.EndGraphEdit(); !S)
		{
			return S;
		}
		for (unsigned Frame = 0; Frame < 3; ++Frame)
		{
			const auto Run = Graph.Execute();
			if (!Run.mStatus)
			{
				return Run.mStatus;
			}
			uint32_t Value = 0;
			if (Bytes->size() != sizeof(Value))
			{
				return FArdaRHIStatus::Error(EArdaRHIResult::InvalidState, "Unexpected readback size.");
			}
			std::memcpy(&Value, Bytes->data(), sizeof(Value));
			if (Value != 123)
			{
				return FArdaRHIStatus::Error(EArdaRHIResult::InvalidState, "Unexpected compute-graph output.");
			}
		}
		return {};
	}

#include "ComputeWriteNode.h"
#include "RecipeNodeSupport.h"
#include <cstring>

namespace arda
{
	class FArdaRecipeComputeShader final : public FArdaGlobalShader
	{
	public:
		ARDA_BEGIN_SHADER_PARAMETER_STRUCT(FArdaParameters)
			ARDA_SHADER_PUSH_CONSTANTS(uint32_t, mValue, 0, 0, EArdaRHIShaderStage::Compute)
			ARDA_SHADER_BUFFER_UAV(mOutput, 0, 0, EArdaRHIShaderStage::Compute)
		ARDA_END_SHADER_PARAMETER_STRUCT()
		ARDA_DECLARE_GLOBAL_SHADER(FArdaRecipeComputeShader);
	};
	ARDA_IMPLEMENT_GLOBAL_SHADER(FArdaRecipeComputeShader,
	    ARDA_RDG_RECIPE_SHADER_DIR "/ComputeWrite.hlsl",
	    "RecipeCompute",
	    "RecipeCS",
	    EArdaRHIShaderStage::Compute)

	struct FArdaComputeWriteNode::FArdaState
	{
		FArdaGlobalShaderMap mShaders;
		FArdaInductorPipelineContribution mStage;
		eastl::shared_ptr<const FArdaInductorPipelineConfiguration> mConfiguration;
	};

	FArdaRHIStatus FArdaComputeWriteNode::DeclareResources(FArdaDependencyResourceContext& C, FArdaParameters& P)
	{
		FArdaRHIBufferDesc D;
		D.mByteSize = D.mStructureStride = sizeof(uint32_t);
		D.mUsage = EArdaRHIBufferUsage::Structured | EArdaRHIBufferUsage::UnorderedAccess;
		return C.Buffer(P.mOutput, "Output", D);
	}

	FArdaDependencyNodeMetadata FArdaComputeWriteNode::GetMetadata()
	{
		return {"recipe.compute-write", 1};
	}

	eastl::string FArdaComputeWriteNode::GetCanonicalKey(const FArdaParameters& P)
	{
		FArdaDependencyKeyBuilder Key;
		Key.Resource(P.mOutput);
		Key.Value(P.mValue); // CPU input record is frozen with this instance.
		return Key.Build();
	}

	TArdaRHIResult<eastl::shared_ptr<const FArdaComputeWriteNode::FArdaState>> FArdaComputeWriteNode::Prepare(
	    FArdaRHIDeviceRef Device)
	{
		if (!Device)
		{
			return {{}, FArdaRHIStatus::Error(EArdaRHIResult::InvalidState, "Compute preparation needs a device.")};
		}

		auto State = eastl::make_shared<FArdaState>();
		if (!State->mShaders.Initialize(Device))
		{
			return {{}, ShaderError(State->mShaders)};
		}

		const auto* Shader = State->mShaders.Find(FArdaRecipeComputeShader::GetStaticType());
		if (!Shader)
		{
			return {{}, ShaderError(State->mShaders)};
		}
		State->mStage.mShader = Shader->GetShader();
		State->mStage.mBindingLayouts = Shader->GetBindingLayouts();
		auto Config = eastl::make_shared<FArdaInductorPipelineConfiguration>();
		Config->mKind = EArdaPipelineStateKind::Compute;
		State->mConfiguration = eastl::move(Config);
		return {eastl::move(State), {}};
	}

	FArdaDependencyNodeDesc FArdaComputeWriteNode::Describe(const FArdaParameters& P, const FArdaState& State)
	{
		FArdaDependencyNodeDesc D;
		FArdaDependencyShaderValue Value;
		Value.mMember = "mValue";
		Value.mBytes.resize(sizeof(P.mValue));
		std::memcpy(Value.mBytes.data(), &P.mValue, sizeof(P.mValue));
		D.BindShader<FArdaRecipeComputeShader::FArdaParameters>({{"mOutput", P.mOutput}}, "default", {Value});
		D.mPipelineStages = {State.mStage};
		D.mPipelines = {{"default", 0, EArdaPipelineStateKind::Compute, {}, State.mConfiguration}};
		return D;
	}

	FArdaRHIStatus FArdaComputeWriteNode::Record(FArdaDependencyExecutionContext& C,
	    const FArdaParameters& P,
	    const FArdaState& State,
	    FArdaInstanceState&)
	{
		// Bind the executor-prepared pipeline and shader arguments before dispatching this operation.
		if (auto S = C.SetComputeState(); !S)
		{
			return S;
		}

		C.GetCommands().Dispatch(1, 1, 1);
		return {};
	}
}

Mesh shader / meshlet pipeline

The node privately registers mesh and pixel shaders, declares an offscreen color output, supplies raster state and requests a Meshlet pipeline. Two instances retain different output textures but share one matching PSO. The GPU test checks creation and replay; it does not compare rendered pixels.

These are compiled recipe sources, built into ArdaGraphTests. In an application, compile all four node .cpp files and the assembly file (it defines all four recipes and the shared registration function), or extract only the assembly function for your selected node, include the private recipe support header, link Ardashir::ArdaRenderGraph, and define ARDA_RDG_RECIPE_SHADER_DIR as an absolute path to the shader directory. Enable on-demand compilation for development, or deploy matching artifacts for load-only mode.

Registration: FArdaMeshTriangleNode::Register() publishes the type; RegisterRecipeLibrary registers all four native recipes together. The renderer only attaches operations and wires their output handles:

FArdaRHIStatus RunMeshRecipe(FArdaRHIDeviceRef Device)
	{
		FArdaDependencyGraph Graph(Device);
		if (auto S = Graph.BeginGraphEdit(); !S)
		{
			return S;
		}
		auto First = Graph.AttachOrFind<FArdaMeshTriangleNode>("mesh A", {});
		if (!First)
		{
			return First.mStatus;
		}
		auto Second = Graph.AttachOrFind<FArdaMeshTriangleNode>("mesh B", {});
		if (!Second)
		{
			return Second.mStatus;
		}
		if (auto S = Graph.MarkOutput(Graph.FindOutput(First.mValue, "Color")); !S)
		{
			return S;
		}
		if (auto S = Graph.MarkOutput(Graph.FindOutput(Second.mValue, "Color")); !S)
		{
			return S;
		}
		if (auto S = Graph.EndGraphEdit(); !S)
		{
			return S;
		}
		// Two instances, matching shader/layout references and attachment formats: one mesh PSO.
		const auto Compiled = Graph.GetPipelineCacheStats();
		if (Compiled.mMeshletEntries != 1 || Compiled.mHits < 1)
		{
			return FArdaRHIStatus::Error(EArdaRHIResult::InvalidState, "Expected mesh PSO reuse.");
		}
		for (unsigned Frame = 0; Frame < 3; ++Frame)
		{
			const auto Run = Graph.Execute();
			if (!Run.mStatus)
			{
				return Run.mStatus;
			}
		}
		return {}; // These offscreen textures are released with Graph. Retain Graph in a renderer.
	}

	FArdaRHIStatus FArdaMeshTriangleNode::Validate(const FArdaParameters& P)
	{
		if (!P.mWidth || !P.mHeight)
		{
			return FArdaRHIStatus::Error(EArdaRHIResult::InvalidArgument, "Mesh target extent must be nonzero.");
		}
		return {};
	}

	TArdaRHIResult<eastl::shared_ptr<const FArdaMeshTriangleNode::FArdaState>> FArdaMeshTriangleNode::Prepare(
	    FArdaRHIDeviceRef Device)
	{
		if (!Device)
		{
			return {{}, FArdaRHIStatus::Error(EArdaRHIResult::InvalidState, "Mesh preparation needs a device.")};
		}

		auto State = eastl::make_shared<FArdaState>();
		if (!State->mShaders.Initialize(Device))
		{
			return {{}, ShaderError(State->mShaders)};
		}

		const auto* Mesh = State->mShaders.Find(FArdaRecipeMeshShader::GetStaticType());
		const auto* Pixel = State->mShaders.Find(FArdaRecipePixelShader::GetStaticType());
		if (!Mesh || !Pixel)
		{
			return {{}, ShaderError(State->mShaders)};
		}
		for (const auto* Shader : {Mesh, Pixel})
		{
			FArdaInductorPipelineContribution Stage;
			Stage.mShader = Shader->GetShader();
			State->mStages.push_back(eastl::move(Stage));
		}
		auto Config = eastl::make_shared<FArdaInductorPipelineConfiguration>();
		Config->mKind = EArdaPipelineStateKind::Meshlet;
		auto& Desc = Config->mMeshlet.mDesc;
		Desc.mRasterState.mCullMode = EArdaRHICullMode::None;
		Desc.mDepthStencilState.mbDepthTest = false;
		Desc.mDepthStencilState.mbDepthWrite = false;
		Desc.mSampleCount = 0; // ArdaInductor completes formats and samples from the framebuffer.
		State->mConfiguration = eastl::move(Config);
		return {eastl::move(State), {}};
	}

	FArdaDependencyNodeDesc FArdaMeshTriangleNode::Describe(const FArdaParameters& P, const FArdaState& State)
	{
		FArdaDependencyNodeDesc D;
		D.mAccesses = {{P.mColor, EArdaDependencyAccess::Write, EArdaRHIResourceState::RenderTarget}};
		D.mColorTargets = {P.mColor};
		D.mPipelineStages = State.mStages;
		D.mPipelines = {{"default", 0, EArdaPipelineStateKind::Meshlet, {}, State.mConfiguration}};
		return D;
	}

	FArdaRHIStatus FArdaMeshTriangleNode::Record(FArdaDependencyExecutionContext& C,
	    const FArdaParameters& P,
	    const FArdaState&,
	    FArdaInstanceState&)
	{
		auto Color = C.GetTexture(P.mColor);
		if (auto S = C.GetCommands().ClearTexture(*Color, {}, {0.f, 0.f, 0.f, 1.f}); !S)
		{
			return S;
		}
		FArdaRHIMeshletState State;
		State.mViewports = {{0.f, float(P.mWidth), 0.f, float(P.mHeight), 0.f, 1.f}};
		State.mScissors = {{0, int32_t(P.mWidth), 0, int32_t(P.mHeight)}};
		if (auto S = C.SetMeshletState(State); !S)
		{
			return S;
		}

		return C.GetCommands().DispatchMesh(1, 1, 1);
	}
}

	    FArdaRHIDeviceRef Device)
	{
		if (!Device)
		{
			return {{}, FArdaRHIStatus::Error(EArdaRHIResult::InvalidState, "Raster preparation needs a device.")};
		}

		auto State = eastl::make_shared<FArdaState>();
		if (!State->mShaders.Initialize(Device))
		{
			return {{}, ShaderError(State->mShaders)};
		}

		const auto* FArdaVertex = State->mShaders.Find(FArdaRecipeRasterVertexShader::GetStaticType());
		const auto* Pixel = State->mShaders.Find(FArdaRecipeRasterPixelShader::GetStaticType());
		if (!FArdaVertex || !Pixel)
		{
			return {{}, ShaderError(State->mShaders)};
		}
		for (const auto* Shader : {FArdaVertex, Pixel})
		{
			FArdaInductorPipelineContribution Stage;
			Stage.mShader = Shader->GetShader();
			State->mStages.push_back(eastl::move(Stage));
		}
		auto Config = eastl::make_shared<FArdaInductorPipelineConfiguration>();
		Config->mKind = EArdaPipelineStateKind::Graphics;
		auto& Desc = Config->mGraphics.mDesc;
		Desc.mRasterState.mCullMode = EArdaRHICullMode::None;
		Desc.mDepthStencilState.mbDepthTest = false;
		Desc.mDepthStencilState.mbDepthWrite = false;
		Desc.mSampleCount = 0; // ArdaInductor completes formats and samples from the framebuffer.
		State->mConfiguration = eastl::move(Config);
		return {eastl::move(State), {}};
	}

	    const FArdaParameters& P,
	    const FArdaState&,

		{
			return S;
		}

		// Supply dynamic draw inputs; the executor fills the compiled pipeline, framebuffer, and bindings.

Work graph

A CPU entry record drives one work-graph node that writes 123. Global resource bindings are generated from the shader struct. The RHI creates program backing storage. Entry records supply scalar inputs: global graph push-constant arguments are rejected for work graphs. D3D12 requires work-graph support; the current Vulkan backend returns Unsupported.

These are compiled recipe sources, built into ArdaGraphTests. In an application, compile all four node .cpp files and the assembly file (it defines all four recipes and the shared registration function), or extract only the assembly function for your selected node, include the private recipe support header, link Ardashir::ArdaRenderGraph, and define ARDA_RDG_RECIPE_SHADER_DIR as an absolute path to the shader directory. Enable on-demand compilation for development, or deploy matching artifacts for load-only mode.

Registration: FArdaWorkWriteNode::Register() publishes the type; RegisterRecipeLibrary registers all four native recipes together. The renderer only attaches operations and wires their output handles:

FArdaRHIStatus RunWorkRecipe(FArdaRHIDeviceRef Device)
	{
		FArdaDependencyGraph Graph(Device);
		if (auto S = Graph.BeginGraphEdit(); !S)
		{
			return S;
		}
		auto Work = Graph.AttachOrFind<FArdaWorkWriteNode>("write", {{}, 123});
		if (!Work)
		{
			return Work.mStatus;
		}
		auto Bytes = eastl::make_shared<eastl::vector<uint8_t>>();
		auto Read =
		    Graph.AttachOrFind<FArdaGraphReadbackNode>("read", {Graph.FindOutput(Work.mValue, "Output"), Bytes});
		if (!Read)
		{
			return Read.mStatus;
		}
		if (auto S = Graph.EndGraphEdit(); !S)
		{
			return S;
		}
		for (unsigned Frame = 0; Frame < 3; ++Frame)
		{
			const auto Run = Graph.Execute();
			if (!Run.mStatus)
			{
				return Run.mStatus;
			}
			uint32_t Value = 0;
			if (Bytes->size() != sizeof(Value))
			{
				return FArdaRHIStatus::Error(EArdaRHIResult::InvalidState, "Unexpected readback size.");
			}
			std::memcpy(&Value, Bytes->data(), sizeof(Value));
			if (Value != 123)
			{
				return FArdaRHIStatus::Error(EArdaRHIResult::InvalidState, "Unexpected work-graph output.");
			}
		}
		return {};
	}

CUDA operation and graphics composition

Build the runnable example from a repository checkout with Visual Studio x64 build tools and an installed CUDA toolkit: python Scripts/Examples/RunPixelSort.py vulkan --hidden --frames 3 --verify. The script configures the PixelSort CMake target, enables CUDA kernel generation, locates the build tools and deploys shaders. Choose d3d12 for the other backend. The command runs the complete example; the excerpts here are node-authoring references, not a separate standalone project.

For the operation's complete implementation, follow the graph parameters, private helpers, operand implementation and CUDA kernel registration and kernel source. These are documentation snapshots of the original files. The example target's generated pixel_sort CUDA profile supplies the host registration symbol referenced by the operand.

CUDA launches do not use graphics PSOs or descriptor tables. A CUDA node supplies an operand to a compiler-coalesced sequence. Logical resources determine dependencies and graphics/CUDA handoffs. The operand schema resolves native CUDA buffers or surfaces; compatible adjacent nodes share an acquisition and release. This is batching of ordered calls on one stream, not kernel fusion.

The complete PixelSort node below owns operand construction, declares a CUDA-shareable output texture and contributes one radix operation. Its PrepareCuda fills the operand's typed host parameters from resolved graph textures. The TArdaCudaOperandNode specialization of the common class base derives accesses and native resource arguments directly from an operand's schema; see automatic CUDA batches. cuBLAS/cuDNN-style calls use the external-call operand contract; capture must be explicitly supported by the adapter and library configuration.

In the complete renderer, attach UploadFrame, take its Constants output, attach Noise with that handle, pass Noise's Output into Sort, and pass Sort's Output into Present. Import only external targets and persistent inputs. FArdaPixelSortSortNode::Register() supports library discovery; typed attachment does it automatically. The operand implementation and kernel are linked by the example's CMake target.

Ray tracing and automatic shader tables

Build and run from a repository checkout with Visual Studio x64 build tools: python Scripts/Examples/RunCornellBox.py vulkan. Documentation snapshots provide the missing authoring context: graph parameters and frame data, private node helpers, PCH includes and ray shader code. The target maps /ArdaTests/CornellBox to its node shader directory; do not treat that virtual shader path as a filesystem root.

The Cornell trace class privately registers ray generation, miss and closest-hit shaders. It names the ray exports and hit group, declares radiance output and maps shader metadata to TLAS, scene buffers and frame constants. The renderer does not allocate a shader table. With one ray-generation export, compilation creates a table containing that export followed by all miss, hit-group and callable records in the resolved pipeline's deterministic order.

Use FArdaCornellTraceNode::Register() for discovery or typed attachment for automatic registration. The complete Cornell renderer imports persistent geometry and acceleration structures, attaches UploadFrame, BuildTLAS, Trace, Accumulate and Present, and wires their declared outputs. BuildTLAS executes every graph call. Its TLAS write orders Trace's TLAS read even if the builder is attached later. BLAS construction/compaction and geometry uploads remain separate operations with their own dependencies.

For several ray-generation exports or custom record order, declare FArdaDependencyShaderTable. Each record's mRecordIndex is dense and zero-based within its category: raygen 0, miss 0, hit-group 0 are three different valid records. The graph converts them to the RHI's flat record array. Exports must exist with the correct stage; holes and duplicate category/index pairs fail compilation.

Per-record mLocalBindings can declare metadata and logical resource arguments. The compiler generates its local layout, associates it with the export or hit group, derives its resource reads/writes and creates a local binding set for each frame slot. Raw local argument bytes use mLocalArguments. Native limits still apply: D3D12 supports these fixed local layouts; the current Vulkan backend requires direct-heap local descriptors and rejects this fixed-local-binding path. Global fixed bindings and automatically generated tables are supported on both tested backends. A default record with required local resources needs an explicit declaration supplying them.

Bindless indices are addresses, not dependencies

A descriptor index selects a view. Two different indices may alias the same bytes, and two views of the same buffer may cover disjoint bytes. The compiler therefore resolves FArdaDependencyBindlessTable entries to resource identity and view ranges before creating dependency edges. Tables are immutable and node-local: different nodes can populate different entries of the same compatible layout. A zero capacity selects one past the greatest populated index, within the declared maximum.

// Inside Describe; P.mBuffer is a shared 256-byte logical buffer.
FArdaDependencyBindlessTable T;
T.mName = "tiles";
T.mCapacity = 2;
T.mLayout.mVisibility = EArdaRHIShaderStage::Compute;
T.mLayout.mRegisterSpace = 0;
T.mLayout.mMaxCapacity = 2;
T.mLayout.mRegisterSpaces = {{0, 2, EArdaRHIBindingType::StructuredBufferUAV}};
FArdaDependencyBindlessEntry E;
E.mArrayElement = P.mDescriptorIndex;
E.mType = EArdaRHIBindingType::StructuredBufferUAV;
E.mResource = P.mBuffer;
E.mView.mBufferRange = {P.mByteOffset, 128};
E.mAccess = EArdaDependencyAccess::Write;
T.mEntries = {E};
D.mBindlessTables = {T};
// A: index 0, offset 0. B: index 1, offset 128.
// Both can request the same compute shader and pipeline configuration.

For buffer intervals A=[0,128) and B=[128,256), the intersection is empty, so neither writer depends on the other. A whole-buffer reader depends on both; a reader of B depends only on B. Removing A removes consumers that require A's bytes and preserves B-only consumers. Changing B to [64,192) creates a region [64,128) with repeated writes. Its overlapping writers and readers follow original successful attachment order; the portions written by only one node retain attachment-independent producer-to-reader ordering. A whole-buffer read still needs coverage beyond byte 192. Texture views use the product of mip, array-slice and plane ranges; arbitrary pixel rectangles are not tracked. See the repeated-write example.

Declare every entry a shader might select, including GPU-selected indices. Use an unrestricted resource view when the accessed range is unknown. Sparse holes must never be indexed. An SRV cannot be declared as a writer. A descriptor table is not itself a data dependency: its populated entries supply those dependencies. Undeclared shader access is outside the graph contract.

To supply an index through shader parameters, put a FArdaDependencyDescriptorIndex relocation in a named FArdaDependencyShaderValue. Identify the table, slot, type and populated array element, plus the byte offset of a uint32 field in that value's bytes. Compilation patches the field after table allocation and the state helper applies the prepared push constants. Ordinary indices are table-relative; absolute heap indices require a direct-heap table with exactly one descriptor bank. Invalid entries or offsets fail compilation.

Independence permits scheduling freedom; it does not guarantee simultaneous GPU occupancy. The executor omits same-state buffer UAV barriers between disjoint ranges while tracking every outstanding unsynchronized access. The RHI still tracks buffer state and queue ownership for the whole buffer, so cross-queue ownership or state changes can impose waits even for disjoint bytes. Separate buffers offer more freedom across queues. Textures track native subresources. Explicit edges, memory-budget ordering and the single CUDA stream can also serialize otherwise independent work.

The compiler compares relevant writer ranges per resource, then validates read coverage: buffer intervals are sorted and merged, and texture coverage is checked over mip/slice/plane cells. Graph-owned reads require complete initialized coverage, possibly from several disjoint producers; imported resources may provide initial contents. Range granularity reduces false edges at the cost of compilation work proportional to access counts and texture subresource cells. Descriptor population is a compilation cost, not free: the current RHI writes table entries individually. Measure large-table compilation separately from steady-state replay.

The bindless GPU conformance test exercises two disjoint UAV views, relocated indices, numerical readback, PSO sharing and repeated table reuse on D3D12 and Vulkan.

Automatic assignment and stable reuse

A pipeline request identifies a family and a local slot. Inference walks dependency ancestry, including through intermediate nodes without shader contributions. It stops at an earlier consumer of the same family, because that consumer already owns a completed pipeline. Stage-only providers set mbPipelineStageOnly, declare no GPU resource work and use a synchronization-domain node class that may omit Record. Connect them with dependency edges; merely attaching a provider nearby does not associate it with a draw.

For example, a vertex provider and pixel provider can feed a pure join, which feeds two draws. Each draw declares its own color output and requests Graphics. Both requests see the same stages through the join. Matching attachment formats and fixed state produce the same stable key and reuse one native PSO. The compiled raster and mesh recipes above test the simpler equivalent case where each consumer owns its stage contributions.

The stable key serializes shader content identities, layout semantics, fixed/program state, ray exports and attachment formats deterministically. It excludes node IDs, debug names, slot/group labels and resource addresses. Generated layouts are interned by the graph. The native in-memory cache also verifies shader/layout object compatibility; a matching hash alone does not authorize reuse. Keeping shader objects in shared node preparation state supports reuse across instances. Replacing RGBA8 with another attachment format, changing blend state or changing shader content creates a different pattern.

Multiple named contribution groups require a selected request group; an ungrouped contribution is shared. Conflicting shaders for one stage/export fail rather than selecting an ancestor by distance or attachment order. See the complete inference rules and the compiler chapter for normalization and boundary behavior.

Registration and compilation failures

  • Missing shader member or wrong descriptor type: attachment or compilation reports an argument/layout error. Supply every resource leaf and array element exactly once, using the shader's metadata, and match push-constant byte sizes.
  • Hidden allocation or descriptor mutation in Record: the compiler cannot account for hidden hazards and replay may use stale bindings. Declare outputs and tables before compilation; keep opaque library workspace in the node's workspace estimate and declare all its data access.
  • Repeated writes: on regions with multiple distinct writer nodes, attach writes and intervening reads in the intended order. Reads consume the preceding writer; an owned read before the first write fails, while imported storage may supply initial contents. ReadWrite needs incoming initialized coverage. Finding a node does not reorder it, and an explicit dependency cannot oppose inferred hazards. Repeated writes reuse one resource; declare separate output handles if older contents must remain available.
  • Incorrect bindless independence: different indices that resolve to overlapping storage still conflict. Narrow a view only when the shader actually stays inside it; shader control flow is not analyzed. Indexing a hole or undeclared resource cannot be made safe by scheduling.
  • Ambiguous pipeline or missing stage: correct the contribution dependencies, select a group or split conflicting consumers. Stage-only nodes cannot own resource accesses, bindings or render targets.
  • Invalid ray table: supply exactly one selected raygen, known exports with the right category and dense category-relative indices. Declare required local arguments explicitly; respect backend local-binding support.
  • Stale identity: the same instance name with a changed canonical key fails. Remove and replace it inside an edit. Include resources, dimensions, shader choices and frozen parameters in the key. Do not mutate an aliased configuration after attachment.
  • Unsupported hardware or artifacts: check the returned status and device capabilities. Work graphs currently require D3D12; CUDA must be enabled and its interop path supported. On-demand shader loading needs source directories; load-only needs deployed matching artifacts.

A failed compile leaves the edit open: correct the declaration and end the edit again, or cancel it. Inspect the graph's diagnostic exports and enable native GPU validation while debugging descriptor or synchronization problems. A successful topology check alone does not validate shader indexing behavior.

Summary and checkpoints

Node classes own operation definitions; the graph owns physical preparation. Resource views determine dependencies, dependency ancestry determines pipeline membership, and normalized state determines reuse. Replay uses retained per-frame objects, while edits rebuild changed semantics.

  1. Why can descriptor indices 3 and 7 still conflict? Resolve their views before comparing ranges.
  2. What changes when a reader covers both halves of a shared output? It joins both producers and must have complete coverage.
  3. Why can two independent buffer ranges still wait across queues? Buffer state and ownership are native whole-object constraints.
  4. When do two draws reuse a pipeline? Their complete normalized state and retained native shader/layout objects must be compatible.
  5. Where is a missing ray-local resource supplied? In an explicit shader-table record declaration before compilation.
