Learning objectives

Choose synchronous or ticket-based execution and interpret queue handoff, readback completion and partial failure.

Synchronous and asynchronous execution

Execute() performs Submit() followed by Wait(), including frames without readbacks. Submit() waits only when recycling an occupied slot. mFramesInFlight controls independent transient pools. IsComplete() polls a ticket.

auto First = Graph.Submit();
if (!First) return First.mStatus;
auto Second = Graph.Submit();
if (!Second) return Second.mStatus;
auto Completed = Graph.Wait(First.mValue);
if (!Completed.mStatus) return Completed.mStatus;
return Graph.Wait(Second.mValue).mStatus;

Native recording

The compiled program resolves resources and automatic pipeline slots before callbacks. FArdaGraphExecuteOptions controls parallel recording, worker count, resource-state validation and adjacent raster merging. Dependent commands inside one callback still need their internal barriers.

Ownership and waits

Dependencies include resource handoff, physical aliasing and shared inter-frame storage. D3D12 uses state transitions and queue fence waits; Vulkan also tracks queue-family ownership. Imports enter and leave on graphics. Used imported textures return to the uniform state captured by a read-only query during compilation; they must be initialized or acquired before that query and cannot enter in Unknown or Discard. Callers must preserve or restore the captured contract before replay. Imported buffers return to descriptor initial state. Retirement waits for this graph’s submissions rather than device-wide idle.

CUDA graph replay

Retained sequences capture kernels and opted-in external calls. Changing graphics interop waits/signals stay outside captured executables. Each frame slot owns caches; exact argument/address variants select bounded cached executables. Disabled, Prefer and Require modes control fallback. See CUDA sequences.

Completion publication

Readback records asynchronous transfers, then publishes host vectors after successful completion. Failed frames clear destinations. Tickets remain valid after slot reuse and edits. Use distinct destinations when several results must coexist.

Nonblocking GPU telemetry

Timing is optional and disabled by default. With mbEnableGpuTiming, sampled frames record per-node timestamps on supported graphics, compute and copy queues. CUDA event regions measure individual semantic nodes within their existing batch, excluding surrounding graphics/CUDA handoffs. Unsupported queues omit samples without queue migration. Stage-only and pure synchronization nodes have no GPU interval.

CollectTelemetry() and Submit() poll completed work and available queries; collection adds no GPU wait. Query setup or polling failures can discard samples without invalidating a successful frame. An unsafe failure ending an already-started native query instead rejects recording and preserves the provider error. Execute() still submits and waits, and asynchronous submission can still wait when recycling an occupied frame slot. GetTimingProfile() exposes EMA statistics; GetTimingHistory() exposes bounded raw node durations.

Optional background scheduling prepares a replacement on a worker while the current program remains active. Adoption reuses the same allocations and waits for no GPU work: it proceeds only when all old frame slots and readbacks can naturally retire. Continuous saturation may defer adoption. Call CollectTelemetry() or keep submitting, and inspect GetAdaptiveSchedulingStats() for pending work and accepted plans. See the configuration and telemetry guide for defaults, sampling overhead and manual requests.

Execution evidence

FArdaGraphExecutionResult exposes status, submitted list count, queue waits/dependencies, pool/alias activity, submission IDs and state conformance. Pass indices identify lowered work, including generated boundaries; they are not semantic node handles. The compile report uses semantic identities.

Partial failures

Failed submission may still carry a ticket for accepted GPU work. Its resources stay retained until retirement. Repair an invalidated execution plan through an edit before retrying. Shared input storage must remain valid until recording and GPU uses complete.

Chapter summary

Submit schedules retained native work; Wait completes this frame and publishes results. Accepted GPU work retains its resources even when later work fails.
