Learning objectives

Build and execute a minimal clear/readback graph, explain consumer-first attachment and handle failed edits.

Libraries and headers

Initialize a native FArdaRHIDeviceRef, link Ardashir::ArdaRenderGraph, and include ArdaDependencyGraphNodes.h. The registry automatically installs upload, buffer-copy, clear, readback and synchronization definitions. CUDA adapters are in ArdaDependencyGraphCuda.h.

Clear and read back three frames

#include "ArdaDependencyGraphNodes.h"
using namespace arda;
FArdaRHIStatus Run(FArdaRHIDeviceRef Device)
{
    FArdaDependencyGraph Graph(Device);
    if (auto S = Graph.BeginGraphEdit(); !S) return S;
    FArdaRHIBufferDesc Desc;
    Desc.mByteSize = 256;
    Desc.mUsage = EArdaRHIBufferUsage::UnorderedAccess;
    auto Output = Graph.CreateBuffer("output", Desc);
    if (!Output) return Output.mStatus;
    auto Bytes = eastl::make_shared<eastl::vector<uint8_t>>();
    auto Read = Graph.AttachOrFind("read", "arda.readback",
        FArdaGraphReadbackParameters{Output.mValue, Bytes});
    if (!Read) return Read.mStatus;
    auto Clear = Graph.AttachOrFind("clear", "arda.clear-buffer",
        FArdaGraphClearParameters{Output.mValue, 7});
    if (!Clear) return Clear.mStatus;
    if (auto S = Graph.EndGraphEdit(); !S) return S;
    for (unsigned Frame = 0; Frame != 3; ++Frame)
    {
        auto Result = Graph.Execute();
        if (!Result.mStatus) return Result.mStatus;
        // Bytes holds 64 uint32_t values, each equal to 7.
    }
    return {};
}

Consumer-first attachment

The readback reads the value produced by clear, so compilation orders clear first. Readback is observable and retains its producer. Use MarkOutput() for a graph-owned output without another observable consumer. Imported and persistent outputs are also roots.

Change semantics through edits

AttachOrFind() reuses a name only when definition and canonical key match. Replace changed operations within an edit. Removing a producer also removes resource-dependent consumers, which must be recreated as needed. Failed compilation leaves the edit open for repair or CancelGraphEdit().

Check every result

Invalid handles, multiple producers, uncovered reads, cycles and ambiguous pipelines fail compilation. Native recording, submission and completion failures propagate through execution status. GPU work already accepted by a queue cannot be rolled back.

Chapter summary

Readback makes the clear output observable; a single successful edit produces the plan reused by all three executions.
