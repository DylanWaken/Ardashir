Learning objectives

Build and execute a minimal clear/readback graph, explain automatic dependencies and handle failed edits.

Libraries and headers

Initialize a native FArdaRHIDeviceRef, link Ardashir::ArdaDependencyGraph, and include ArdaDependencyGraph.h. The registry automatically installs upload, buffer-copy, clear, readback and synchronization definitions. CUDA adapters are in ArdaDependencyGraphCuda.h.

Clear and read back three frames

#include "ArdaDependencyGraph.h"
using namespace arda;
FArdaRHIStatus Run(FArdaRHIDeviceRef Device)
{
    FArdaDependencyGraph Graph(Device);
    FArdaGraphEdit Edit(Graph);
    FArdaRHIBufferDesc Desc;
    Desc.mByteSize = 256;
    Desc.mUsage = EArdaRHIBufferUsage::UnorderedAccess;
    const auto Output = AllocateBuffer(Edit, Desc, "output");
    Clear(Edit, Output, 7);
    const auto Bytes = Readback(Edit, Output);
    if (auto S = Edit.Commit(); !S) return S;
    if (auto S = Graph.Compile(); !S) return S;
    for (unsigned Frame = 0; Frame != 3; ++Frame)
    {
        auto Result = Graph.Execute();
        if (!Result.mStatus) return Result.mStatus;
        // Bytes holds 64 uint32_t values, each equal to 7.
    }
    return {};
}

Parameters belong to each operation

Each node class declares its own FArdaParameters struct. Use the named global callable published by its header: ClearNode(Edit, FirstBuffer, uint32_t{7}). Positional fields aggregate-initialize the node's parameter schema in declaration order, including defaults for omitted fields. The same callable accepts positional fields, a prefilled parameter value, or an initializer callback. The operation retains an immutable snapshot:

FArdaGraphClearNode::FArdaParameters Parameters;
Parameters.mDestination = FirstBuffer;
Parameters.mValue = 7;
ClearNode(Edit, Parameters, "clear first");

ClearNode(Edit,
    [&](FArdaGraphClearNode::FArdaParameters& P)
    {
        P.mDestination = SecondBuffer;
        P.mValue = 42;
    }, "clear second");

The callback runs synchronously once before validation or preparation and may return FArdaRHIStatus. Do not retain its temporary reference or edit the graph inside it. Each invocation creates a new operation; optional names are diagnostic and must be unique. Resolve node-owned outputs through GetBuffer(Slot) or GetTexture(Slot) before closing the edit. One Edit.Commit() reports the first authoring error and queues only successful work.

Automatic dependencies

Readback consumes the value produced by clear, so compilation orders clear first and retains its producer. Use Edit.Keep(Resource) for an owned output without another observable consumer. Resource types select operation overloads: CopyTo supports buffer-to-buffer, texture-to-texture and both mixed transfer directions. For a dependency that has no resource access, use Edit.Order(ProducerOperation, ConsumerOperation).

Change semantics through edits

After execution, record the next frame in a new edit on the same graph. Its construction starts empty; omit unwanted operations without removing their old nodes. Close each edit, then call Compile(). Matching ordered constructions reuse a persistent revision. Successful compilation locks edits until execution is attempted. A failed compilation retains queued edits for a correction edit or DiscardPendingEdits().

Check every result

Invalid handles, uncovered reads, contradictory dependencies, cycles and ambiguous pipelines fail compilation. For repeated writes to an overlapping region, attach writers and intervening readers in their intended order; the resource example shows which contents each read observes. Regions with one producer still allow readers to be attached first. Native recording, submission and completion failures propagate through execution status. GPU work already accepted by a queue cannot be rolled back.

Chapter summary

Readback makes the clear output observable; a closed edit followed by successful compilation selects the plan reused by all three executions.
