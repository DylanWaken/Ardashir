How to read this reference

Namespace and names

The public graph API lives in arda::render_graph. Qualified names identify the owning namespace or class; short names are convenient search terms but can match overloads, template specializations, or members on several types. Types under arda::rhi are backend objects consumed by the graph, not graph-owned logical declarations.

Handles and raw logical references

TARDGHandle<TagType> and aliases such as FARDGPassHandle are compact, type-safe indices into append-only registries. An invalid handle names no entry. Types ending in Ref, such as FARDGTextureRef, are nullable raw pointers to graph-owned logical records; they are neither owning smart pointers nor physical RHI resources. Keep both forms within the builder that created them and within that builder’s lifetime.

Builder phases are contracts

Treat a builder as a one-graph state machine. During setup, allocate or provide parameters, create or import logical resources and views, register passes, request extraction, and add explicit dependencies. Compile freezes the graph’s device-independent schedule and derives culling, lifetimes, barriers, queues, and groups. Execute compiles when needed, materializes resources, records command lists, and submits once. An entry’s Errors and details state when a call is illegal after compilation or execution; these phase restrictions are correctness rules, not performance advice.

Fatal checks and nullable lookup

A documented fatal check means a violated programming contract invokes the project’s check path; it is not a recoverable status result. This is used for conditions such as null required inputs, invalid metadata, undeclared physical access, and illegal phase transitions. In contrast, functions named TryGet* deliberately return nullptr for invalid handles, and FARDGBlackboard::TryGet returns nullptr when a type is absent. Use the nullable forms when absence is expected; use checked forms only when absence is a bug.

Ownership, imports, and extraction

The builder owns graph records and copied or arena-allocated parameter storage. A resource created with Create* is logical until execution materializes physical backing; a resource passed to RegisterExternal* remains externally owned while the graph tracks its declared entry state and uses a retained RHI reference. QueueTextureExtraction and QueueBufferExtraction request that graph-created physical storage survive graph completion and write the resulting RHI reference to caller-provided output storage after submission. The output location must remain valid through Execute; extraction transfers a durable reference, not ownership of the logical graph record.

CPU submission is not GPU completion

A successful Execute result reports completion of CPU-side compilation, recording, and queue submission. It does not mean the GPU has finished the submitted work. The returned queue instance values describe submitted work; use the RHI device’s synchronization and completion facilities before reading results on the CPU, reusing externally constrained memory, or destroying objects whose lifetime is not retained by the submission system.

The unsafe command-list escape hatch

FARDGPassExecutionContext validates physical resource access through getters such as GetTexture, GetBuffer, and CreateBindingSet. Its mUnsafeRawCommandList member exists for commands that cannot be expressed through those helpers. It does not make undeclared graph-resource access safe: independently retained RHI references bypass declaration validation, so the compiler cannot infer their dependencies, transitions, or lifetimes. Prefer the validated context and keep raw command-list use narrow and explicit.

Parameter macros and templates

Read ARDG_BEGIN_PARAMETER_STRUCT and ARDG_END_PARAMETER_STRUCT as generating a standard-layout C++ struct plus immutable reflection metadata. A macro such as ARDG_TEXTURE, ARDG_BUFFER_UAV, or ARDG_RENDER_TARGET_BINDING_SLOTS declares both a C++ member and its graph access semantics; *_ARRAY variants repeat that contract, nested-struct macros recurse, and direct *_ACCESS members carry runtime state or range information. For templates, substitute the documented type parameters before reading the signature: ParameterType must expose generated static metadata where required, and an ExecuteType callback must match one of the supported pass-lambda forms. Overloads and macro entries are separate canonical symbols even when their visible names are similar.
