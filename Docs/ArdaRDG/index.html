Learning objectives

Explain persistent graph ownership, edit boundaries and replay, and choose the appropriate authoring guide.

A reusable compute and graphics program

FArdaDependencyGraph owns named typed nodes, logical resource versions and an ArdaInductor execution plan. It retains physical resources, inferred pipelines and CUDA executable caches. Attach consumers before producers when convenient: declared values determine ordering.

Edit, compile, replay

Open BeginGraphEdit(), create or import resources, attach nodes, then call EndGraphEdit(). Successful compilation publishes a revision. Repeated Execute() calls use that revision. Submit() and frame tickets expose asynchronous completion. Reopen an edit when semantics change.

Working examples

The triangle renderer (Source/ArdaTests/RHITest/Private/ArdaTriangleRenderer.cpp) assembles vertex upload, index upload and draw nodes in its first graph, then retires the uploads and caches draw graphs per swap-chain image. The terrain renderer (Source/ArdaTests/Examples/ARDGExample/Private/ArdaTerrainRenderer.cpp) assembles separate settings/camera uploads, settings copy, heightmap generation, erosion, triangulation, depth-tested drawing, overlay and optional readback nodes. Intermediate resource values let ArdaInductor infer their execution order even when consumers are attached first. Both release cached backbuffers before resize.

The declaration contract

  • Each logical value has one producer.
  • Declare every native resource access with state and range.
  • Semantic parameters and shader settings stay immutable between edits.
  • Imports are retained and restored to their entry state and graphics-queue ownership.
  • Check all edit, attachment, execution and completion statuses.

Capabilities and limits

Graphics, meshlet, compute, ray-tracing and work-graph pipeline requests depend on backend capabilities. CUDA libraries need declared accesses and the framework stream; capture requires explicit adapter support. Bounded search retains a feasible plan within its work budget. Python tracing and discovery of hidden library accesses are outside this API.
