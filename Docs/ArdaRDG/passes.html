Passes and parameters

A pass combines a name, behavior flags, frozen parameter data, generated metadata, and an execution callback. The parameter declaration is the compiler-visible contract: callback code is not inspected to discover resource dependencies.

Learning objectives

After this chapter, you should be able to:

  • Select legal pass flags and a supported callback form.
  • Define standard-layout ARDG parameter structs with values, arrays, nested structs, resources, views, accesses, uniform buffers, and raster bindings.
  • Explain how frozen metadata visitation produces pass state and dependency history.
  • Distinguish RAW/WAW producer edges from WAR synchronization-only edges and explain their different culling behavior.
  • Use raster binding slots, AddDispatchPass, the blackboard, and shader metadata binding helpers correctly.
  • Keep raw command-list access narrow and preserve declaration completeness.

Prerequisites

Read Resources and ownership. You should understand logical versus physical storage, graph-local handles, state declarations, SRVs, UAVs, and whole-resource dependency precision.

Setup and execution are separate

AddPass freezes parameters and immediately visits metadata while the graph is built. The callback runs later while an RHI command list is recorded. Mutating the original parameter object after registration does not change the frozen copy.

Fundamentals: a pass is declared work

AddPass registers a typed lambda pass in stable handle order. The stored record contains immutable parameter storage and metadata; setup derives resource states, logical views, raster attachments, uniform-buffer references, and incoming edges. Compilation later decides liveness, queue pipeline, transitions, and recording waves.

The parameterless AddPass overload stores no metadata. It therefore contributes no automatic resource declarations or hazard edges. Use it for genuinely parameterless side effects, combine it with NeverCull when observability requires it, or add explicit causality with AddDependency.

Pass flags and lambda forms

EARDGPassFlags describes operation category and scheduling constraints:

Raster
Graphics work with declared render-target bindings.
Compute
Compute dispatch on a graphics-capable pipeline.
AsyncCompute
Requests async compute and must be combined with Compute. Queue capability and state compatibility still decide whether compilation uses it.
Copy
Requests copy-queue work; all resource states must be copy compatible.
NeverCull
Makes the pass an observable liveness root even without extracted/external output.
SkipRenderPass
Valid only with Raster; the callback manages framebuffer behavior explicitly.
NeverParallel
Records the pass serially even when parallel recording is enabled.

Raster cannot combine with compute, async, or copy. Copy cannot combine with compute or async. Unknown bits are rejected during registration.

Typed callback forms

The typed overload accepts every shape below. The parameter-first forms are distinct supported overloads selected by the private invocation helper:

  • (FARDGPassExecutionContext&, const ParameterType&) — preferred;
  • (const ParameterType&, FARDGPassExecutionContext&);
  • (IArdaRHICommandList&, const ParameterType&) — unsafe raw form;
  • (const ParameterType&, IArdaRHICommandList&) — unsafe raw, parameter-first form;
  • (FARDGPassExecutionContext&);
  • (IArdaRHICommandList&) — unsafe raw form;
  • (const ParameterType&); or
  • ().

Parameterless passes accept context, raw command list, or no arguments. Unsupported signatures fail at compile time.

The ARDG parameter DSL

ARDG_BEGIN_PARAMETER_STRUCT and ARDG_END_PARAMETER_STRUCT generate a C++ struct plus one immutable GetStaticMetadata() object. Member macros generate both storage and semantic metadata.

Ordinary values
ARDG_PARAMETER and ARDG_PARAMETER_ARRAY preserve callback data but contribute no graph access.
Default reads
ARDG_TEXTURE, ARDG_BUFFER, and SRV forms imply shader-resource state.
Default writes
ARDG_TEXTURE_UAV and ARDG_BUFFER_UAV imply unordered-access state.
Runtime access
ARDG_TEXTURE_ACCESS, ARDG_BUFFER_ACCESS, and ARDG_ACCEL_STRUCT_ACCESS carry explicit state plus range information where applicable.
Uniform buffers
ARDG_UNIFORM_BUFFER declares a graph uniform buffer and recursively visits resources referenced by its frozen contents.
Nesting
ARDG_PARAMETER_STRUCT embeds another generated parameter struct. Array variants exist for every repeatable family.
Raster attachments
ARDG_RENDER_TARGET_BINDING_SLOTS declares color and depth/stencil output slots.

Metadata layout, standard layout, arrays, and nesting

The generated metadata records member name, semantic type, byte offset, total size, alignment, element count, element stride, default state, and optional nested metadata in FARDGParameterMember. FARDGParameterMetadata stores struct name, size, alignment, and declaration-ordered members.

ARDG_END_PARAMETER_STRUCT statically requires standard layout because metadata uses offsetof and byte arithmetic. AllocateParameters<T> imposes the same requirement. Standard layout does not mean trivial destruction: graph-arena allocation registers a destructor when needed.

  • Arrays are represented by one member descriptor with count and stride. Enumeration produces paths such as Inputs[2].
  • Nested structs recurse and produce dotted paths such as Material.Textures[1].
  • Nested container records are omitted by default; leaf members are visited.
  • Metadata construction rejects null names, zero count/stride, out-of-bounds layout, and missing nested metadata.

Setup visitation: metadata becomes pass state

Registration first appends the pass, giving it a stable handle later than its existing predecessors. Setup then visits leaves in declaration order:

  • plain values are ignored for graph state;
  • texture/buffer records add default or explicit state and range;
  • views preserve exact view identity and visit their parent storage;
  • uniform buffers are deduplicated per pass and recursively visited;
  • acceleration structures add direct state;
  • raster slots add attachment signatures and render-target/depth-write accesses;
  • null resource leaves are intentionally ignored.

Every non-null logical pointer is checked against the current builder registry. An Unknown explicit access state is a programming error.

Producer-reader hazard algorithm and culling

Each logical texture, buffer, or acceleration structure stores one latest writer and the set of readers since that write. This is the graph's source-backed implementation of RAW, WAR, and WAW hazards. For each declaration:

  1. Any access receives a producer edge from the latest writer, if present.
  2. A read joins the current reader epoch.
  3. A write receives synchronization-only edges from all current readers, clears that epoch, and becomes the latest writer.
RAW — read after write
The reader depends on the last writer. This producer edge preserves the writer when the read contributes to an observable output.
WAW — write after write
The later writer also depends on the last writer. It preserves deterministic replacement order and producer liveness.
WAR — write after read
The later writer must not begin before earlier reads finish, but those readers do not produce the new value. Synchronization-only edges order live work without making an otherwise dead reader live.

Edges are whole-resource; barriers can be finer

The history above ignores texture subresource and buffer-range separation. Texture mip/slice ranges survive into per-subresource transition lowering; buffer ranges survive validation while buffer transitions remain whole-resource. This conservative edge policy can reduce parallelism but does not weaken correctness.

Culling starts from the epilogue and NeverCull roots and walks only producer edges. A manual AddDependency is also a producer edge and therefore affects both execution order and liveness.

Raster binding slots

FARDGRenderTargetBindingSlots contains a fixed color array indexed by RHI render-target slot and one depth/stencil binding. Each binding carries a logical texture and selected subresources.

Setup records color textures as RenderTarget writes and depth/stencil as DepthWrite. It also builds an attachment signature from logical handles and ranges. Compilation groups adjacent graphics raster passes only when their signatures are identical and neither uses SkipRenderPass. Group metadata does not itself merge command lists or native render passes.

Unused color slots remain null. Attachment declarations are graph state; the callback still binds compatible pipeline, framebuffer, viewport, scissor, and draw state through the RHI.

AddDispatchPass

AddDispatchPass wraps typed AddPass, always adds Compute, invokes a setup callback, then calls Dispatch(x, y, z). The setup callback must bind the compute pipeline and bindings; the helper supplies only the final dispatch dimensions.

Its default is graphics-capable compute. Add AsyncCompute to request the compute queue. Compilation falls back to graphics when the queue is unavailable, immediate mode is active, or declared states are incompatible. Thread-group counts are groups, not shader threads.

Graph-scoped typed blackboard

FARDGBlackboard stores at most one copy-constructible value per C++ type. Use GetBlackboard() during building to Set, Emplace, or GetOrCreate shared declarations such as scene textures. Get checks that a type exists; TryGet returns null when absence is expected.

The mutable builder accessor closes after building. A const accessor remains available later. The blackboard communicates graph-scoped CPU values; storing a logical pointer there does not itself declare any pass access. The consuming pass must still place it in its parameters.

Shader metadata binding bridge

CreateBindingSet(shaderMetadata, layout) validates that the layout can be generated from registered shader metadata, flattens shader members, and matches compatible ARDG parameter leaves in declaration order. Register space, visibility, slot, array element, and binding type must agree.

The global-shader overload CreateBindingSet(shader, layoutIndex) selects one generated layout directly; CreateBindingSets builds every layout in order. A layout-only overload assigns independent sequential SRV, UAV, and constant-buffer slots.

  • Texture and buffer resources/views become binding items with physical resources and declared view ranges.
  • Uniform buffers become constant-buffer items.
  • Acceleration-structure access can become a ray-tracing acceleration-structure binding.
  • Plain values, direct texture/buffer accesses, nested containers, and raster slots are not descriptor bindings.
  • Every layout array element must be matched; missing or incompatible declarations trigger the check path.

This is a metadata bridge, not binary reflection: authored ARDG semantics are reconciled with registered shader parameter metadata and RHI binding layouts.

The unsafe command-list escape hatch

FARDGPassExecutionContext exposes validated GetTexture, GetBuffer, GetAccelStruct, GetUniformBuffer, and binding-set helpers. They require an active callback, verify graph ownership and exact view declaration, and reject undeclared physical access.

mUnsafeRawCommandList exists because not every RHI command has a typed graph wrapper. It does not make independently retained RHI references visible to graph analysis. Any graph resource used through it must still be declared in parameters and resolved through the context when possible. The deprecated mCommandList alias has the same bypass risk.

Unsafe means the compiler cannot prove completeness

A raw callback can read or write an external RHI object without a graph edge, transition, lifetime, or queue wait. Reserve this form for narrow commands that cannot use validated helpers, and document any independently synchronized external object.

Design derivation

  1. Graph compilation needs resource accesses before callbacks execute.
  2. C++ parameter structs provide convenient typed callback data, but C++ alone has no runtime member reflection.
  3. The macro DSL generates stable layout metadata alongside ordinary members.
  4. Freezing gives metadata a stable immutable instance to enumerate.
  5. Declaration-order visitation produces deterministic states, views, bindings, and hazard history.
  6. Separating producer from synchronization edges lets WAR impose safety without incorrectly retaining dead readers.
  7. Validated execution getters check that callback behavior remains inside the declared graph contract.

Worked example: compute to raster declaration

Illustrative pseudocode

This example emphasizes graph declarations and dependency flow. It omits app-specific shader objects, pipeline-state cache and initializer setup, graphics state and framebuffer construction, swap-chain acquisition, dispatch dimensions, and draw arguments.

using namespace arda::render_graph;

ARDG_BEGIN_PARAMETER_STRUCT(FLightingParameters)
    ARDG_TEXTURE_UAV(Output)
ARDG_END_PARAMETER_STRUCT()

ARDG_BEGIN_PARAMETER_STRUCT(FCompositeParameters)
    ARDG_TEXTURE_SRV(Lighting)
    ARDG_RENDER_TARGET_BINDING_SLOTS(RenderTargets)
ARDG_END_PARAMETER_STRUCT()

FARDGTextureRef lighting = graph.CreateTexture(lightingDesc);
FARDGTextureUAVRef lightingUAV = graph.CreateTextureUAV(
    "Lighting.UAV", {lighting->GetHandle(), {0, 1, 0, 1}});
FARDGTextureSRVRef lightingSRV = graph.CreateTextureSRV(
    "Lighting.SRV", {lighting->GetHandle(), {0, 1, 0, 1}});
FARDGTextureRef backBuffer = graph.RegisterExternalTexture(
    swapchainTexture,
    rhi::EArdaRHIResourceState::Present,
    "BackBuffer");

auto* lightingParameters = graph.AllocateParameters<FLightingParameters>();
lightingParameters->Output = lightingUAV;

graph.AddDispatchPass(
    "Lighting",
    lightingParameters,
    {groupCountX, groupCountY, 1},
    [&lightingShader, &pipelineStateCache, &lightingInitializer](
        FARDGPassExecutionContext& context,
        const FLightingParameters&)
    {
        rhi::FArdaRHIComputeState state;
        state.mBindings = context.CreateBindingSets(lightingShader);
        (void)pipelineStateCache.SetComputePipelineState(
            context.mUnsafeRawCommandList,
            lightingInitializer,
            eastl::move(state));
    },
    EARDGPassFlags::AsyncCompute);

auto* compositeParameters = graph.AllocateParameters<FCompositeParameters>();
compositeParameters->Lighting = lightingSRV;
compositeParameters->RenderTargets.mColor[0] =
    {backBuffer, {0, 1, 0, 1}};

graph.AddPass(
    "Composite",
    compositeParameters,
    EARDGPassFlags::Raster,
    [&compositeShader, &pipelineStateCache,
     &compositeInitializer, &graphicsState, &fullscreenDrawArguments](
        FARDGPassExecutionContext& context,
        const FCompositeParameters&)
    {
        auto state = graphicsState; // includes a compatible framebuffer
        state.mBindings = context.CreateBindingSets(compositeShader);
        (void)pipelineStateCache.SetGraphicsPipelineState(
            context.mUnsafeRawCommandList,
            compositeInitializer,
            eastl::move(state));
        context.mUnsafeRawCommandList.Draw(fullscreenDrawArguments);
    });

The compute parameter declares a UAV write to lighting. The raster parameter declares an SRV read of the same logical texture, creating a RAW producer edge from Lighting to Composite. If async compute is selected, compilation emits a cross-queue dependency; otherwise same-queue order applies. The texture range drives the UAV-to-shader-resource barrier, while the dependency itself is whole-texture.

The raster binding slot declares a render-target write to the imported back buffer. That observable external write anchors the composite pass at the epilogue, which in turn keeps the compute producer live. The callbacks use shader metadata to create bindings, then use the raw command list only for state and draw/dispatch commands that the context does not wrap.

Pass and parameter invariants

  1. A pass is named, has a callable body, and uses a legal flag combination.
  2. Typed parameters expose generated metadata and satisfy standard layout.
  3. Parameters are frozen before setup and remain immutable through callback execution.
  4. Every graph resource used by a callback appears in that pass’s declarations with a truthful state and range.
  5. All logical pointers and views resolve in the same builder.
  6. RAW/WAW/manual producer edges carry liveness; WAR synchronization edges carry order only.
  7. Whole-resource edges are not confused with subresource-specific texture barriers.
  8. Raster flags, attachment declarations, pipeline, framebuffer, and callback commands agree.
  9. Shader metadata, ARDG parameter order/types, and binding layout agree for every required element.

Performance and threading

  • Keep pass declarations coarse enough to amortize command-list and submission cost, but expose meaningful producer boundaries.
  • Use precise texture ranges to reduce barriers. Current whole-resource edges can still serialize disjoint ranges, so measure before splitting passes for subresource concurrency.
  • Use AsyncCompute only for compatible, substantial work with useful overlap. Queue waits and bandwidth contention can erase gains.
  • Avoid NeverCull unless the pass has a real side effect not represented by graph output.
  • Avoid NeverParallel unless callback CPU code touches thread-affine or unsafely shared state.
  • Parallel recording invokes independent callbacks concurrently. Capture immutable state or provide synchronization; never mutate shared graphics state, allocators, or descriptor data without a threading contract.
  • Use uniform buffers to share frozen parameter trees deliberately; recursive visitation is deduplicated per pass.
  • Prefer shader metadata overloads over positional layout-only binding when registered metadata exists; validation catches slot and array mismatches earlier.

Tradeoffs

Macro metadata versus handwritten declarations
The DSL adds generated boilerplate and a standard-layout constraint, but keeps C++ storage and graph semantics synchronized.
Frozen copies versus late mutation
Freezing makes compilation and parallel recording deterministic at the cost of copying stack-authored parameters.
Conservative edges versus concurrency
Whole-resource tracking is easier to validate and less expensive than per-range histories, but can over-order disjoint work.
Automatic edges versus explicit dependencies
Resource declarations express data flow naturally. AddDependency covers non-resource causality but can accidentally retain work because it is a producer edge.
Validated context versus raw command list
The context proves declaration membership. The raw list exposes the full RHI but can bypass the graph’s knowledge.

Summary

Pass registration freezes typed parameters and visits generated metadata to derive states, views, raster attachments, uniform-buffer recursion, and hazard history. RAW and WAW produce liveness-carrying producer edges; WAR produces synchronization-only order. Current edge discovery is whole-resource even when texture barriers target specific subresources. Raster slots declare attachments, AddDispatchPass standardizes compute dispatch, the blackboard shares graph-scoped values, and shader metadata bridges declarations to binding sets. Validated context getters preserve the contract; raw command-list access remains an explicit escape hatch.
