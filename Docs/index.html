Ardashir documentation

Build graphics and GPU compute workloads in C++. Record commands against the rendering hardware interface (RHI), or describe operations and resource dependencies in a graph that you can compile and run across frames.

How the graph compiler works

Follow a workload from resource declarations through dependency analysis, queue scheduling, memory reuse, and GPU completion. The essay also explains how the offline model frontend packages kernels for execution. How Arda turns a graph into GPU work

Graphics backend

ArdaBackend defines the interfaces for devices, resources, shaders, pipelines, and command lists. The native providers implement those interfaces for Direct3D 12 and Vulkan. ArdaBackend overview

Project modules

ArdaInfra contains the backend and native providers, ArdaNativeCompute, ArdaGraph, and ArdaDependencyGraph. The source tree also contains ArdaTests and ArdaTrace.

ArdaDependencyGraph

Declare operations and resource accesses. ArdaInductor derives dependencies, plans storage, and schedules work.

ArdaNativeCompute

Register native GPU kernels and shader implementations behind one operation and resource contract.

ArdaGraph

Generic directed graph storage, generational handles, traversal and graph algorithms used by infrastructure clients.

ArdaTests

Runnable graphics and CUDA examples and shared backend test support. Start with the graphics examples or Pixel Sort walkthrough.

ArdaTrace records CPU scopes, counters, and markers for offline analysis.

The archived scene representation plan describes proposed scene layers. ArdaBackend handles native device and resource interoperability.
