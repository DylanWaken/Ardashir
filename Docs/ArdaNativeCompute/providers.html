Choose a GPU provider

An operand can offer several implementations of the same operation. Register the providers your application can use, then put the preferred implementation first in the operand.

Match the kernel to its execution path

ProviderGraphics backend and queueKernel and resource bindings
nvapiD3D12 graphics or computeDXIL compiled with NVIDIA HLSL shader intrinsics. Uses D3D12 shader views directly.
cuda-in-graphicsD3D12 graphics, or Vulkan graphics or computeCUDA kernels or qualified library calls on a device initialized for CUDA in Graphics (CiG). Resources must expose the required CUDA representations.
cudaQualified D3D12 or Vulkan graphics or compute queue, subject to the device’s CUDA launch modeLinked CUDA kernels, PTX, cubin, CUDA C++ or library calls. Accepts an ordinary CUDA context.

Register a compute or graphics shader fallback on the same operand to run on other hardware. Source compilation and device checks happen during preparation, before commands are recorded.

Run a CUDA kernel in graphics

Include CUDA/ArdaNativeCudaProvider.h. Register CreateArdaNativeCudaInGraphicsProvider() and CreateArdaNativeCudaProvider(), checking each returned status. Add the kernel once with AddArdaNativeCudaVariants(operand, variant). Both variants share its source, argument layout and launch policy.

To require CiG, choose the graphics-queue CUDA mode when creating the device, then set context.mPreference = EArdaNativeComputePreference::NativeOnly and context.mRequiredProviderId = ArdaNativeCudaInGraphicsProviderId. A device using an ordinary CUDA context fails this check. With automatic routing, the registry tries the next eligible variant.

D3D12 captures CUDA work on its graphics list. Vulkan uses a CiG context associated with the graphics device and orders CUDA work with graphics through semaphores. Qualify the actual buffer or texture as well as the device. A driver may support a shared linear buffer and reject a shared image. CUDA queues and resource handoffs

Use an NVAPI shader intrinsic on D3D12

This shader writes the lane index of each of 32 threads into a raw buffer. Reserve the extension UAV in a separate register space. Space zero holds the output.

#define NV_SHADER_EXTN_SLOT u0
#define NV_SHADER_EXTN_REGISTER_SPACE space1
#include "nvHLSLExtns.h"

RWByteAddressBuffer Output : register(u0, space0);

[numthreads(32, 1, 1)]
void WriteLane(uint index : SV_GroupIndex)
{
    Output.Store(4 * index, NvGetLaneId());
}

Save the shader as lane.hlsl and compile it from the repository root with DXC. Ship the resulting DXIL with the application.

dxc -T cs_6_0 -E WriteLane -I ThirdParty/NVAPI -Fo lane.dxil lane.hlsl

Register CreateArdaNativeNvapiProvider() once. Pass the DXIL bytes to the source factory. Declare the shader’s extension UAV slot, register space, and every required opcode. The provider queries the active D3D12 device for those opcodes and builds the compute pipeline through NVAPI.

#include "NVAPI/ArdaNativeNvapiProvider.h"
#include "nvShaderExtnEnums.h"  // Add ThirdParty/NVAPI to the shader author's include path.

using namespace arda;

FArdaRHIStatus RegisterLaneIndex(FArdaNativeComputeRegistry& registry,
    eastl::vector<uint8_t> dxil)
{
    FArdaNativeNvapiSourceDesc source;
    source.mDxil = eastl::move(dxil);
    source.mRequiredOpcodes = {NV_EXTN_OP_GET_LANE_ID};
    source.mExtensionUavSlot = 0;
    source.mExtensionRegisterSpace = 1;
    auto shader = CreateArdaNativeNvapiSource(eastl::move(source));
    if (!shader) return shader.mStatus;

    FArdaNativeOperandDesc operand;
    operand.mId = "example.lane-index";
    operand.mResources = {{"Output", EArdaRHIResourceType::Buffer, EArdaComputeAccess::Write}};
    operand.mVariants.push_back({"lane-id", shader.mValue, {}});
    return registry.RegisterOperand(eastl::move(operand));
}

Bind a 128-byte buffer view with Raw | UnorderedAccess usage and prepare the operation for one group. DXIL fixes the block size and shared memory. Use mGridSize for group counts and leave the other launch fields at their defaults. On a raw RHI list, transition the output to UnorderedAccess and call CommitBarriers() before recording the plan. A graph pass declares the same write state so the scheduler can order the transition. Submit the recorded command list. Record and submit an invocation

For additional bindings, operand slot i maps to ti for reads and ui for writes in space zero. Buffer offsets and sizes must be multiples of four, and offsets must meet the device’s storage-buffer alignment. Texture views select a mip. The handoff state is NonPixelShaderResource for reads and UnorderedAccess for writes. Scalar parameters are packed as 32-bit constants at b0. The extension UAV uses one DWORD of the D3D12 root signature. The remaining 63 DWORDs cover resource tables and constants.

Check the selected implementation

Use CheckSupport before allocating provider-specific storage. Call Prepare with the final views, then inspect GetRoute() and GetVariantName(). A missing driver, opcode, or resource representation can send an operation to its shader fallback. Register a shader fallback
